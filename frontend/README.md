# ATLAS · 吉达单港供应保障 Agent Demo

一个以 CUI 发起、GUI 同步生成的整车供应链演示。故事从两周后抵达吉达港的一船 1,800 台 Toyota / Lexus 开始，覆盖单港危机下的船次分车、物流执行，以及到港完成后的每日订单调拨。

## 两个阶段

1. `T-14 → T+3`：分析达曼港关闭影响，把 620 台已预订订单与 1,180 台补库车辆分配到同一组 VIN，形成五条运输路线，并在到港后 2–3 天完成交付与 VPC 入库。
2. `T+4 起`：每天读取 4S / 5S 店订单，从 VPC、门店和授权车商库存中生成正常发货、跨区调拨、偏远拼单或回购方案。

## 五个 Skill

- `/crisis-brief`：单港影响研判
- `/vessel-allocation`：1,800 台船次分车
- `/delivery-plan`：单港物流与板车配载
- `/arrival-execution`：到港后 72 小时执行
- `/daily-rebalance`：每日订单调拨与回购

所有分析都从右侧 CUI 输入 `/` 后选择 Skill。选择只带出默认提示词；按回车后，CUI 的数据读取、业务规则和校验记录与中间 GUI Block 同步流式生成。左侧参考 `frontend_alpha`，使用工作空间、项目和任务会话结构；已经生成的分析在顶部「画布历史」回看，不再使用故事步骤导航。

三个核心工作台展示数据、规则、候选比较与决策结果，CUI 中「查看判断依据」跳转到对应步骤：

- 分车：保护 620 台订单，展示 780 台明确补货的覆盖缺口公式、400 台机动/缓冲以及 VIN 归属。调整达曼安全库存，真实重算利雅得与达曼落地量；应用参数会使旧结果失效，需要从 CUI 重跑。
- 物流：比较直达/经 VPC 的成本、交期和装卸，查看 8 板位批次；模拟利雅得容量 650 → 570 台，展示 80 台需回压的 VIN，已预订订单不受影响。模拟不修改正式计划；实际容量校验失败则阻断发布和到港执行。
- 调拨：逐单比较 VPC、门店、车商等车源的余量、时效、物流成本和净贡献，显示排除原因；企业订单展示 40+24+16 台组合。审批后生成运输任务并锁定车辆。

历史快照可测算但不能应用参数或重复审批。每日调拨按 T+4、T+5…生成独立订单和决策 ID。

## 可解释的决策图

- 分车关系图：按「业务输入 → 筛选与决策 → 计算与约束 → 业务结果」展开，点击节点查看规则与数量依据；在图内调整达曼安全库存，即时查看情景变化，尚未采用的情景不会改写正式计划。
- 物流地图：五条运输路线共用沙特地理底图，点击路线查看数量、交期与费用；可叠加已淘汰的达曼中转路径。实线表示当前方案，虚线表示淘汰路径。
- 车源关系图：展示可用候选、硬约束排除和最终组合；选中车源可查看库存、权属和履约条件。通过筛选不代表已经选中。

底图采用 Natural Earth 公共领域地理轮廓，随演示离线提供，不依赖在线地图服务。运输连线是业务路径示意，不是导航线路；节点支持键盘选择，窄屏可在图内横向浏览。

## 演示顺序

依次运行：

```text
/crisis-brief
→ /vessel-allocation
→ /delivery-plan
→ /arrival-execution
→ /daily-rebalance
```

未满足前置条件时，Agent 会解释缺少的结果，不会自动补做或生成虚假计划。授权车商车辆在权属、价格和付款授权未确认前，只作为不可执行候选。

## 模拟边界

- 全部数据均为确定性演示数据，不连接真实订单、车辆、价格或承运商系统。
- 展示的是可解释的业务规则与情景计算，不是真实 AI 后端或生产级优化求解器；覆盖目标、报价与 8 位装载模板均为演示策略。
- 需求维度：订单池 620 台 + 库存池 1,180 台 = 1,800 台。
- 运输维度：西部 520 + 利雅得 650 + 东部直达 360 + 利雅得截流 170 + 达曼安全库存 100 = 1,800 台。
- 每个 VIN 只有一个有效归属；重复分配、重复签收和未确认权属均会被阻断。
