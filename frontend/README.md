# ATLAS · 吉达单港供应保障 Agent Demo

一个以 CUI 发起、GUI 同步生成的整车供应链演示。重点是 1,800 台供给如何先满足已订订单、再按门店 WoS 补库，以及单港和双港下如何分批送到门店。

## 两类业务上下文

1. 门店计划模拟：data 的 79 家丰田 / 20 家雷克萨斯门店、品牌独立，订单和补库分别计算；同店支持部分直送、VPC 暂存和后续配送。改变参数会重算数量、成本和交期。
2. 原有 VIN 级执行上下文：从已发布计划跟踪清关、发运和签收，形成库存基线后处理每日订单。它与门店模拟独立；模拟完成不代表真实执行完成。

## 八个 Skill

- `/crisis-brief`：单港影响研判
- `/vessel-allocation`：订单优先与门店 WoS 注水分车
- `/delivery-plan`：到店物流、VPC 暂存和单港 / 双港比较
- `/arrival-execution`：到港后 72 小时执行
- `/daily-rebalance`：每日订单调拨与回购
- `/daily-transfer`：每日调拨，企业大单集结、双端影响与异常重排
- `/profit-analysis`：销售贡献利润，订单 / 车型 / 门店的收入、采购和物流成本拆解
- `/smart-query`：智能问数，独立分析销量预测、渠道库存与陆路运输成本

所有分析都从右侧 CUI 输入 `/` 后选择 Skill。选择只带出默认提示词；按回车后，CUI 的数据读取、业务规则和校验记录与中间 GUI Block 同步流式生成。左侧参考 `frontend_alpha`，使用工作空间、项目和任务会话结构；已经生成的分析在顶部「画布历史」回看，不再使用故事步骤导航。

三个核心工作台展示数据、规则、候选比较与决策结果，CUI 中「查看判断依据」跳转到对应步骤：

- 分车：未配订单单独输入，默认 0，已锁库存不重复算订单。1800 台默认补库 1800 台，距目标仍缺 912 台；展示本体图谱、逐步注水和全部门店结果。
- 物流：按每店接车条件与能力拆分直送和 VPC 暂存，安排后续到店批次；比较单港、双港的已知干线小计及按期订单，完整费用待确认。停车场资格不等于可接收全部分配车辆。
- 调拨：逐单比较 VPC、门店、车商等车源的余量、时效、物流成本和净贡献，显示排除原因；企业订单展示 40+24+16 台组合。审批后生成运输任务并锁定车辆。

门店计划历史快照保留原参数和结果，可作为新模拟的输入；重跑不覆盖历史。每日调拨历史快照不能重复审批，T+4、T+5…生成独立订单和决策 ID。

## 滚装船基本统计

`/vessel-allocation` 默认打开「基本统计」，其余 Tab 为「订单分车 / 注水演示 / 门店结果」。首个 Tab 使用 **2026-08-05 独立模拟快照**，覆盖丰田与雷克萨斯、34 家直营店和 45 家授权店，11 张图按五组展示：

- 本船车型供给、2025-07 至 2026-07 每月代表船次对比。
- 渠道订单、车型订单缺货、未来四周车型补库缺口；缺口按总数量降序。
- 吉达、达曼、利雅得三个 VPC 的历史周销速与当前库存。
- 五个区域的历史周销速与当前门店库存。
- 79 家门店近八周的周均销量、当前库存；两图共用销速降序，图内横向滚动查看所有门店。

图表支持鼠标与键盘查看明细，CUI 的「查看基本统计」可定位此 Tab，并可导出独立 JSON 统计快照。车型、订单、VPC 库存、8 月库存和霍尔木兹海峡影响均为明确模拟设定；源供给表仅用于规模参考。基本统计没有将 2026-09-29 源库存冒充 8 月库存，也不随旧分车情景的品牌、供给或 WoS 参数变动。注水演示与门店结果延续原有品牌级数据和参数，CUI 分别说明两种快照的日期与口径。

## 订单分车与物流建议

Tab2「订单分车」沿用基本统计的 **1,694 台订单需求、1,642 台本船可分配、52 台缺口**。车型与渠道数量保持一致，按门店八周销速生成模拟订单号及零售、大客户、展厅三类明细；缺口不进入物流车次。

- 左侧显示全部 79 家门店的沙特地图，圆圈面积代表订单笔数，门店按城市中心展开并避开重叠。点击圆圈或使用门店选择器，右侧展示按车型和订单类型统计的车辆数量柱状图，数量降序。
- 切换「物流建议」，选择吉达单港或吉达 + 达曼双港；右侧展示可分页的建议车次，支持筛选多点卸货。选择车次联动地图，显示卸货顺序、数量和分摊成本；明细保留各站门店、对应订单号、车型、全车总成本与每台物流成本。
- 8 台/车，邻近城市合车且最多 3 个卸货点。费用 = 沿线最高整趟情景报价 + 120 SAR × 额外卸货点 + 400 SAR × 运送数量（港口处理 150、整备 250）。部分装载仍计整趟费用；不含 VPC、跨港调拨与海运。筛选保留完整车次，避免把部分载货误当整车报价。
- CUI 的「查看订单分车 / 查看物流建议」直接定位对应视图。可输入 `/vessel-allocation 订单分车` 或 `/vessel-allocation 物流建议 单港`，并导出含订单与两个港口方案的 JSON 快照。原分车图谱保留在底部「品牌注水情景」折叠区。

订单号、类型、成本和路线均为模拟建议；底图离线提供，路线不表示真实道路。此 Tab 与可编辑品牌级注水情景分别注明口径，不随品牌情景参数重跑而改变。

## 智能问数

在 CUI 输入 `/` 选择「智能问数」，回车运行 `/smart-query`。无需先完成分车或到港流程。CUI 逐步展示思考、执行计划、模拟工具调用、口径校验与总结；GUI 随进度生成三个 Tab：

- **销量与预测**：总量（直营 + 授权）、区域、服务 VPC、门店四种月度折线视图，模拟预测用虚线。门店默认展示所选期间销量前 5 家，可搜索并多选对比；保留逐月渠道明细。
- **库存与渠道**：实物/可用/锁定/冻结/在途、库龄、覆盖周数和补库缺口，支持直营与授权比较。
- **陆路运输成本**：沙特物流路线地图联动双港口/吉达单港场景与门店筛选；按始发港区分线路，线宽表示周运力，虚线表示缺口。点击线路或选择地图路线可查看距离、报价和周运力；同城接驳以环线表示。保留整趟与满载单台费、去重路线周运力明细。

月份、区域、服务 VPC、门店、渠道和品牌筛选联动，可下钻并导出当前视图的 CSV。过程记录中的查看按钮跳转到对应 Tab，结果可从画布历史回看。问数不修改船次、库存或调拨业务状态。

数据来自根目录 `data/`，运行 `npm run data:sync` 更新 `src/lib/query-data.json`。历史销量截至 2026-07，2026-08/09 缺失；8—10 月预测采用最近三个有效月的日均销量，逐门店、品牌计算。库存只有 2026-09-29 快照，不构造历史库存流水。模拟服务关系为吉达→西部/南部、利雅得→中部/北部、达曼→东部，VPC 视图是服务门店汇总。运输使用源数据中的固定场景报价与周运力，满载单台费为整趟报价除以 8。工具调用与预测均为确定性本地演示。

地图素材保存在 `src/lib/query-map-data.json`，使用 [Natural Earth](https://www.naturalearthdata.com/) 公共领域国界与城市数据，并用 [GeoNames](https://www.geonames.org/)（[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)）补齐胡拜尔、海米斯穆谢特与欧奈宰。地理数据经简化；港口/VPC 以对应城市中心定位，曲线表示物流连接关系，不表示真实道路轨迹。距离和费用以业务路线源数据为准，运行时不加载远程地图服务。

## 可解释的决策图

- 分车图谱使用椭圆与直线依赖；注水演示支持播放、暂停、步进和拖动，深色表示有效库存，青色表示新增补库；订单车单列，库存已经超过目标的门店不强制补库。
- 到店路径拆分：按门店展示发出港、服务 VPC、直送与经 VPC 数量。批次表保留完整路径、订单 / 补库量、计划到店日和干线费用分摊。
- 车源关系图：展示可用候选、硬约束排除和最终组合；选中车源可查看库存、权属和履约条件。通过筛选不代表已经选中。

底图采用 Natural Earth 公共领域地理轮廓，随演示离线提供，不依赖在线地图服务。运输连线是业务路径示意，不是导航线路；节点支持键盘选择，窄屏可在图内横向浏览。

## 演示顺序

依次运行：

```text
/vessel-allocation 供给=1800 直营WoS=3 授权WoS=4
→ /delivery-plan 单港到店模拟
```

分车 Skill 可直接运行。GUI 可编辑供给、渠道 WoS、渠道偏移、在途假设与各店未配订单，并通过“模拟重跑”保存新画布。物流绑定所选分车结果，支持部分直送、VPC 暂存、后续时段；数据没有独立 VPC 库存明细，不额外生成车源；通过“路线地图 / 到店路线 / 港口比较 / 到店批次”分析成本与承诺时间。CUI 过程链接可定位对应 GUI 结果，参数与结论随画布保存，刷新可恢复。

智能问数仍可通过 `/smart-query` 独立运行。到港执行与每日调拨需另有已发布 VIN 级计划及实际库存基线；门店模拟不会自动发布、生成签收或解锁执行。

## 物流地图与利润

物流地图以共享城市路线为主维度，展示本轮计划量、已路由量、周运力缺口、整趟报价和干线小计。选择路线后切换“计划批次”，按门店下钻直送/VPC及 D+ 到店日。连线为示意，数据没有真实班次号。物流参数中的“补充物流费用”可填入演示费率或编辑港口、PDI、末端、VPC处理、暂存日费与天数；空值为未知，零为已明确零费用。完整预算还需落实所有路线。

完成物流后，点击“分析订单、车型和门店利润”，或在 CUI 选择 `/profit-analysis`。贡献利润 = 未税折后净收入 − 采购 − 物流 − 佣金 − 其他归属费用。GUI 三个视图可下钻订单，查看收入与成本桥，编辑销售情景和物流费率、切换单港/双港后重跑。每次保存独立画布，并绑定所选物流结果，历史和刷新均可恢复。

`data/05_利润` 是新增的明确模拟数据，包含车型价格/采购成本及补充费率。销售情景取绑定门店中的少量车辆，不能把全部补库车当作售出。利润采用门店平均物流摊分，没有实际 VIN/订单成本绑定；税费和固定经营费用暂不包含。缺成本、缺价格或订单数量超过可路由量时，利润保持待确认。

CUI 参数示例：`/delivery-plan 双港 演示费率`；`/profit-analysis 车型=海拉克斯 单价=90000 采购=110000`；`/profit-analysis 整备=待确认`。财务字段也可用“折扣=、佣金=、其他=”；物流字段用“港口费=、整备=、末端=、VPC费=、暂存日费=、暂存天数=”。

## 模拟边界

- 全部数据均为确定性演示数据，不连接真实订单、车辆、价格或承运商系统。
- 展示的是可解释的业务规则与情景计算，不是真实 AI 后端或生产级优化求解器；覆盖目标、报价与 8 位装载模板均为演示策略。
- 门店模拟采用 data 的 79 家丰田 / 20 家雷克萨斯门店，销速与库存保持来源口径。无未配订单、车型和 VIN 明细，订单默认 0，供给为情景输入。
- 物流基线：单港直送 557 台 + 经 VPC 1070 台 + 未落实 173 台；同店可部分直送、部分暂存。路线周运力同城共享，报价按整趟计费，缺少末端/VPC费用时完整成本待确认。
- 零销速门店不自动补库；目标已满时保留剩余供给。库存 E 采用当前自由库存快照；来源没有在途 ETA，按期在途仅作为显式假设。
- 路线、整趟报价和共享周运力来自 data；接车时段、VPC 额度为情景输入。容量不足显示未落实，缺少后续时段保留未知 ETA。
- 原有 VIN 级执行和每日调拨模型保留独立快照与校验，不与上述门店模拟混用。
