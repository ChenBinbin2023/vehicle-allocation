# 整车供应链 Agent：Dashboard 与关键指标设计

> 版本：v1.1｜日期：2026-09-29
> 配套故事：[周度分货、物流执行与每日调拨](./02_周度分货_物流执行_每日调拨_Agent故事线.md)。
> 目标：让供需、任务、过程指标共同服务于业务决策，并能追到具体车辆、订单和执行记录。
> 数据依据：[数据基线与逐车型分车口径](./04_数据基线与逐车型分车口径.md)。源数据集模拟值、G/H供给、车型参数和模拟回执分别标识。页面与刷新频率属于设计建议。

## 1. 信息结构：全国总览、今日任务、逐车型计划与执行

| 页面 | 首要使用者 | 核心问题 | 核心展示与动作 |
| --- | --- | --- | --- |
| 供需总览 | 供应链与区域负责人 | 全国供给、区域库存和车型需求是否匹配？ | G/H月供给、79店库存、车型压力及港口场景，下钻进入车型计划 |
| 今日任务 | 分货、物流、渠道与财务人员 | 今天先处理哪一个车型、哪一批车？ | 车型分货确认、发运收货、调拨和回购，带责任与截止时间 |
| 分货计划 | 分货与销售负责人 | 每个车型给谁、多少、为什么？ | 15个独立车型任务，再汇总品牌和全国结果 |
| 物流执行 | 物流负责人、VPC与门店 | 所有车型共同使用的路线能否完成任务？ | 双/单港口、路线和班次，共享占用、到达及异常 |
| 每日调拨 | 区域、渠道与供应链负责人 | 今天缺的这个车型和配置在哪里？ | 三类调拨、同车型双端库存、权属与交易条件 |

每个页面中的品牌总额都能展开到车型。车型未拆分时显示“仅品牌数据”，不能展示成已经核实的车型库存。分类为“轿车/SUV”的视图可以辅助汇总，分货操作仍以具体车型和配置为单位。

### 1.1 全局筛选与基线

- 业务范围：品牌→车型→配置、五个大区、18城市、79门店、直营/L2、交易身份和权属。
- 时间与供给：供给参考月、虚构完整经营周W1、各源时间窗口、库存快照和执行日期。
- 港口场景：SC-DUAL双港口、SC-WEST仅西部。默认入口假设可替换，现有结果不适用于未经重算的仅东部场景。
- 版本：供给与车型参数、数据快照、各车型分货版本、共同物流版本、原发布基线与实绩。
- 数据性质：G/H源值、既有模拟数据、新增车型结构假设、模拟执行回执、未来接入的企业实绩。

显示“7月全国月供给8,901台”“按7月强度折算的W1供给2,010台”，不将两者相加。车型参数尚未获得更细数据支持时，页面直接标识“按演示结构拆分”。

全国、品牌、区域、门店的实物库存均来自同一门店底表；账户汇总是另一视图，不能再加上去。99个门店×品牌组合不表示99家门店。

### 2.3 供给与库存分别按车型追溯

供给层按月度基准、车型拆分、计划周、入口承接和实际释放分层。入口切换改变承接计划；未有确定交接条件的批次保持待落实，不进入实际可用。

库存层展示物理位置、权属和状态三个维度。源表只有门店库存，港口/VPC库存需要独立数据；不能由月供给减门店销量倒推出VPC现货。L2的自由库存仍受交易或授权条件限制。

逐车型矩阵显示：供给释放、实际/参考销速、自由库存、已锁、冻结、及时在途、订单需求、补库需求、分配、留存和缺口。没有车型库存/订单时保留缺数状态；供给394不意味着394台凯美瑞已经到港。

### 2.4 总览关键指标

默认按品牌→车型→配置，再按区域、渠道与门店下钻。业务事件到达后重算；源CSV为静态数据，不能显示成实时刷新记录。

| 编号 / 指标 | 定义与计算 | 数据与行动边界 |
| --- | --- | --- |
| A0 全国月供给与周度情景 | 各品牌G/H；七日强度=月供给/实际月天数×7；每品牌取整后逐车型分配 | 7月8,901、W1 2,010。切月重算，不将情景称为实际可用量 |
| A1 本周确认可用供给 | 去重的车型配置批次中，具有调度权且释放时间已确认落在本周的车辆；分列已释放和后续可释放 | 必须有批次和时间数据。未补齐时不直接使用A0的2,010作为确认数 |
| A2 当前自由库存与可调度量 | 源表自由库存5,232；再按权属、车型、配置、时效及其他限制判断可调度子集 | L2自由不等于总部可调；VPC另表，不包含在5,232中 |
| A3 库存覆盖WOS/DOS | 参考WOS采用源表自由库存/参考周销速；逐车型正式覆盖采用同口径需求，并明确是否核销订单，DOS以日需求作分母 | 不把品牌WOS复制给所有车型；原参考销速未核销已锁订单，不能直接改称订单核销后覆盖 |
| A4 按期可满足订单比例 | 同一原承诺窗口中，已按期到店或有确认车源和可行运输可按期到店的互斥车辆集合/全部有效订单车辆需求 | 没有订单明细时不可算；1,223台已锁库存不是分母 |
| A5 净补库缺口 | 逐门店、逐车型配置计算日库存投影及目标缺口，再扣本轮及时新增分配，各明细正缺口相加 | 源表2,107仅是品牌参考。车型拆分后重算，不能强行要求仍等于2,107 |
| A6 港口场景道路压力 | 基准视图采用源表全网和逐路线缺口；分货视图用实际拟发车型明细对共享容量重算 | SC-WEST源表540与548分开展示。不是客户逾期数，也不与供给流量差相加 |

A3需求为0显示“无预计消耗”，缺输入则不可算。A4中未知配车、交期或运力的需求单列待核实，不默认为满足。

## 3. Dashboard B：今天要做的事

### 3.1 顶部指标与任务分组

顶部仅保留“今日应办”“今日已办”“已超时未办”“阻塞事项”四个数。下方分成两个视图：

- **待我决定：** 分货发布/修订、预留释放、跨店调拨、回购条件、费用或交期例外。
- **待执行与跟进：** 承运确认、装车发运、收货签收、异常核查、回购结算、跨周在途。

流程标签采用分货、物流、调拨、回购，可多选筛选。数量统计按独立待办 ID 去重，不把一个带多个标签的事项计算多次。

### 3.2 任务行设计

| 字段         | 应显示的内容                                                    |
| ------------ | --------------------------------------------------------------- |
| 待办名称     | 动词 + 对象，例如“确认 T03 回购条件”“跟进凯美瑞跨周到店” |
| 发起原因     | 周计划、新订单、客户取消、运力变更、回执差异等                  |
| 业务影响     | 关联订单/车辆数、原承诺时间、源地影响；影响集合按车辆去重       |
| 截止与优先级 | 剩余可操作时间、业务优先级及原因，不能只有红黄绿                |
| 当前状态     | 待处理、处理中、待外部反馈、完成、取消或被替代                  |
| 阻塞条件     | 谁的哪个确认尚缺，或者哪条数据尚未到达                          |
| 责任人       | 当前负责人和需要协同的角色                                      |
| 建议动作     | 一个明确的下一步，点击可见依据、备选与影响                      |

默认排序为：已经超时且仍有业务影响 → 最晚发运/确认时间临近 → 新出现的订单风险 → 普通补库与复盘。业务优先级可以调整，但必须展示理由。

“待外部反馈”不是完成状态。若车辆发运窗口已经错过，任务转成明确的异常跟进，不只延长待办截止时间。

### 3.3 任务指标口径

默认按负责人、流程、区域、任务状态拆分。任务事件刷新，待办与超时判断建议分钟级更新。

| 编号 / 指标     | 定义                                                                         | 处理边界                                                  |
| --------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------- |
| B1 今日应办数   | 截止时间为今日的有效待办，加上从此前结转且尚未完成的超时待办，按待办 ID 去重 | 当日新增、取消、被替代分别列出；任务量不等于车辆数        |
| B2 今日已办数   | 今日实际完成的有效待办数                                                     | 分列完成今日应办与清理历史积压；不直接用 B2/B1 作为完成率 |
| B3 已超时未办数 | 截至当前时刻，截止时间已过且仍未完成的有效待办数                             | 因外部反馈阻塞也保留；取消或被替代不伪装成完成            |
| B4 阻塞事项数   | 缺少前置数据、资源或业务确认而无法推进的有效待办数                           | 可与 B3 重叠，二者不能相加成为总待办                      |

工作台另提供“今日到期任务办结率”，按同一到期日任务队列统计截至当日结束已完成数/有效任务数；日内使用截至当前已到期队列，避免把尚未到点的任务判失败。所有历史待办清理量另列。

## 4. Dashboard C：每个车型的独立分货计划

### 4.1 先看到15个任务，再汇总全国结果

任务列表的每一行是一个独立车型：11个丰田车型，4个雷克萨斯车型。默认列为供给、数据完整性、待满足订单、净补库、拟分配、留存、未满足需求和共享运输校验状态。

选中凯美瑞，进入 `W1-TOYOTA-CAMRY`，显示其394台W1情景供给及各配置、来源批次，再展开区域→渠道→门店。切换海拉克斯或LX时，进入相应车型自己的数据、规则和结果；车型间不共用车辆池。

品牌与全国汇总是各车型结果之和。一个“车型结构选择器”不能替代独立分车：每个车型必须有分配明细、约束、版本和未满足原因。

### 4.2 单车型工作页

```text
车型与配置 / 本车型供给及批次 / 输入快照 / 参数版本
订单与库存证据 / 门店销速及目标 / 直营与L2规则
本车型方案对比 / 各门店分配明细 / 留存与缺口
共同运输反馈：哪些线路、时段与其他车型冲突
发布状态 / 原计划与当前差异 / 关联运输和调拨
```

车型草案可分别计算，但发布前合并全部车型检查路线容量、VPC/门店库容、资金等共享约束。利雅得352台容量只能出现于同一资源账一次，不能为15个车型各分配352。

### 4.3 因素与参数

| 因素 | 本车型页面的证据 | 处理方式 |
| --- | --- | --- |
| 供给结构 | G/H→车型→周→批次和配置的数量链 | 本次车型比例是显式参数，源月各品牌守恒 |
| 需求与库存 | 门店×本车型的销速、订单、自由库存和及时在途 | 缺细分数据时显示缺项，不按供给比例复制需求和库存 |
| 渠道保底 | 对本车型生效的保底、已由订单覆盖部分 | 历史品牌70%/90%直营分摊比例不自动成为各车型新配额 |
| 配置与交期 | 年款、动力、等级、颜色、原承诺 | 未允许替代的配置分别匹配 |
| 库龄与贡献 | 本车型实际/模拟明细、统一收入成本主体 | 不用品牌平均利润强排全部车型 |
| 物流反馈 | 同路线其他车型占用、时段与装载冲突 | 返回受影响车型重算，维持其来源与去向守恒 |

### 4.4 关键指标

按车型版本计算后汇总。输入齐全的车型可形成可执行计划，输入不足的车型保留草案；不因总体数据有数就将全部15个任务显示完成。

| 编号 / 指标 | 计算口径 | 使用方式 |
| --- | --- | --- |
| C0 车型任务进度 | 15个任务按待数据、草案、待物流校验、待确认、已发布互斥分组 | 显示具体卡在哪个车型、哪个条件 |
| C1 订单按期计划覆盖率 | 与A4同口径，按本车型原承诺窗口计算 | 尚无订单时不预填100% |
| C2 净补库按期分配覆盖率 | 本车型已分配且按要求到店或可按期到店的补库量/同窗口冻结的本车型净补库需求 | 逐车型计算；品牌汇总用分子分母加总，不平均百分比 |
| C3 未满足需求 | 本车型未配订单、未获补库分配、已分配但延期分别列示 | 476台车型流量正差不能代替本指标 |
| C4 本车型供给分配与留存 | 同一车型供给队列按订单分配、补库、缓冲、未决去向互斥分组 | 例如凯美瑞队列总计394，T01释放12后仍为394 |
| C5 运输可执行率 | 经共同资源与本车型装载、交期、收货检查通过的拟配送量/该车型拟配送总量 | 352的共享线路能力不复制给每个车型 |
| C6 原计划到店兑现率 | 原发布版本在窗口内应到车辆中，按原日期实际到店的去重数量/同队列原应到车辆数 | 需要发布与回执数据。批准延期也保留原基线偏差 |

全国品牌级参考补库2,107不是C2的逐车型分母来源。细化车型后需重新计算，保留与品牌参考的差异说明。

## 5. Dashboard D：物流执行与过程指标

### 5.1 页面结构

顶部指标：今日应发/已发、到期应到/已到、按时发运、按时到店、异常影响车辆及运输费用。

中部按运输段展示甘特图和任务表，可以切换来源为“周分货”或“每日调拨”。同一运输段中混装两类来源时，用车辆明细标注，段级总量去重。

地图可展示在途与预计到达，但必须同时可读到原计划时间、最新预计时间、最新回报时点和相关订单影响。缺少定位时标“位置待更新”，不绘制虚构实时轨迹。

### 5.2 关键指标

默认按路线、运输段、承运商、班次、来源流程、车型占位类型和目的区域拆分。事件到达刷新，建议五分钟内更新异常影响。物流负责人维护计划、承运及签收数据。

| 编号 / 指标               | 定义与公式                                                                                                   | 口径及下钻                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| D1 到期发运完成率         | 冻结计划中截至当前应发车辆—运输段记录，已实际发运的记录数 ÷ 同队列应发记录数                               | 同一辆车两段运输计两次车辆段工作量；显示应发、已发、未发                          |
| D2 按时发运率             | D1 同一到期队列中，实际发运时间不晚于原计划最晚发运时间的记录数 ÷ 应发记录数                                | 到期未发也留在分母；更改班次不能抹掉原延误                                        |
| D3 运输段按时签收率       | 原计划到达截止已到期的车辆—运输段记录中，按原截止实际签收的记录数 ÷ 应签收记录数                           | 未签收仍在分母；中转到 VPC 只计这一段，不计最终订单到店                           |
| D4 已确认订单按期到店率   | 原承诺到店日已到期的有效订单车辆需求中，按原承诺在指定交付门店签收并完成匹配的数量 ÷ 同队列有效订单车辆数量 | 不等同于消费者提车；全国结果由实际或模拟订单与回执计算，不从已锁库存推造订单总数             |
| D5 运力利用率             | 已执行班次中已装车辆的等效占位合计 ÷ 同班次合法可用占位合计                                                 | 使用加权汇总，不平均各班次百分比；按装载模板另查尺寸重量，利用率高不代表合法装载  |
| D6 异常影响车辆           | 存在有效物流异常且影响交期、状态或交接的 VIN 去重数                                                          | 一车多个异常只计一次，按原因展开；事件数另列                                      |
| D7 单位运输费用与预算差异 | 同一运输任务队列实际归集费用 ÷ 该队列实际承运车辆段数；另示实际费用 − 冻结预算                             | 单位 SAR/车辆段，按路线与车型分组。待结算费用单列估计，费用数据不齐不声称最终成本 |

D4 是全链路履约结果，D3 是某运输段服务水平，不能互相替代。D1–D3 的辆数明确标为“车辆段”，避免与供给量或到店去重车辆混用。

现有路线合并了港口/VPC起点，不凭同一条容量数据直接拆出两段可执行运输。SC-WEST与SC-DUAL分别统计，不把两个场景的180辆板车累加。统一8台/车次是源模型参数，逐车型混装还要检查尺寸、重量与装载模板。

跨日、跨周运输继续保留同一任务和车辆身份。统计时根据指标分别使用计划应发日、计划应到日、订单原承诺日或实际事件日，不统一用运单创建日期。

## 6. Dashboard E：每日调拨与过程指标

### 6.1 页面结构

顶部显示当天新增待满足需求、按期可解决数量、已确认/已到店调拨量、超时量，以及回购待确认与待结算事项。

中部三类任务共用一张表，也可按 VPC→门店、门店→门店、回购后配送切换。选中任务，右侧出现源地与目标地两个库存面板：现货、锁定、自由库存、调前/调后水位、影响订单、可用运输时间。

下方是候选方案对比，统一显示最早到达、原承诺、源地损失、费用、可执行条件与确认状态。回购方案增加交易主体、权属交接和结算状态。

### 6.2 关键指标

默认按需求提出日、原承诺日、调拨类型、区域、来源和目的门店、车型配置拆分。库存、订单与调拨事件刷新，候选确认前必须使用最新有效状态重新校验。区域和渠道负责人共同负责来源及需求确认。

| 编号 / 指标           | 定义与公式                                                                                               | 口径及下钻                                                       |
| --------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| E1 今日新增调拨需求量 | 当天新进入调拨池的有效需求车辆数，扣除同一需求重复提报和已由原有库存/安排及时覆盖的数量                  | 单位辆；另列结转、取消和改配。本组追加演示事件为20；须先核销预测，不能称源CSV中的新增订单   |
| E2 按期可解决比例     | 选定需求队列中，已有来源锁定、必要交易条件和可行运输，预计能按原承诺到店的车辆数 ÷ 该队列有效需求车辆数 | 候选报价不算落实；T03 未确认时本例最高17/20=85%，确认后20/20     |
| E3 调拨按期到店率     | 原要求到店截止已到期的调拨需求车辆中，在原截止前到达目标地并匹配原需求的数量 ÷ 同队列有效需求车辆数     | 按任务来源队列去重，不能仅以已经完成的调拨作分母；注入对应模拟回执后，本组可显示20/20，不代表全国订单履约  |
| E4 调拨响应时长       | 从有效需求进入调拨池，到首次形成来源与执行条件均确认的方案之间的时长，展示中位数与P90                    | 单位小时；未落实需求另外显示等待时长和超时量，防止只看已完成样本 |
| E5 调出后水位合规率   | 已确认调拨中，在调出时点满足有效订单保护与源地最低自由库存的源地×配置×调出批次检查数 ÷ 全部应检查数   | 单位%；缺数据单列未校验，不视为通过；后续持续缺货另成异常        |
| E6 调拨费用           | 同一调拨队列的运输、交易、补偿、资金等已确认新增费用，分列预计、实际和待结算                             | 内部调拨与回购分组比较。回购车辆采购价另列，不能混成运输单价     |
| E7 回购执行与结算     | 候选、可执行、已取得调度权、已到店、已结算分别列辆数和单数；另列未付/未结金额与到期日                    | 状态可能并行，不能相加成回购总量；三辆到店不意味着财务已结清     |

E2 是计划能力，E3 是实绩。E3 与 D4 可能引用同一批订单到店事实，在各自业务视角展示即可，不把二者分子加起来称“保障交付总量”。

T01的12台凯美瑞属于W1供给394台的子集，只改变用途；T02的5台RAV4来自期初门店存量；T03的3台LX先确认L2的权属与交易。三者不自动增加2,010台供给。源表只有品牌库存，调拨前须补足对应车型与配置。店间和回购配送需要新路线或报价，不套用439.74 SAR的全网满载均价。

不默认展示“调拨节约金额”“回购利润提升”。只有取得同一需求、同一窗口下的可行基线，以及一致的收入、费用和期末库存处理，才计算方案差额。单次回购转售贡献不能直接替代相对收益。

## 7. 统一计算与数据规则

### 7.1 需求、库存与来源集合

合理补库的计算可以采用以下表达，但必须统一需求窗口：

```text
目标自由库存 = 目标覆盖天数 × 本车型配置同口径预计日均未覆盖需求
净补库需求 = max(0, 目标自由库存 − 当前自由可用现货 − 窗口内及时自由在途)
补库分配后缺口 = max(0, 净补库需求 − 本轮可及时满足该补库的新增分配)
```

“及时自由在途”不包含已匹配订单或已被其他需求占用的车辆。本轮新增分配一旦转为在途，按同一车辆从“本轮分配”迁移为“在途”，不能在两个减项里同时扣除。逐日检查可用与需求发生时点，不用周末来车抵周初缺口。

预测已包含的订单先做核销；原补库车辆被新订单消耗后，相应调整补库与订单归属。只有净增部分进入新增需求。取消订单释放的库存需先获得有效取消记录，再参与其他分配。

源表的品牌参考缺口可直接呈现，但以上正式逻辑下沉到门店×车型×配置后必须重算。每个状态的车型拆分合计对回原门店品牌状态；供给、销速、库存使用各自的数据或参数，不能只套同一比例。W1参考消耗2,405和期初品牌参考缺口2,107属于不同时间及业务概念，不能直接相加为订单需求。

### 7.2 库存与运输守恒

```text
单地点期末实物库存 = 期初实物库存 + 实际收货 − 实际发出 − 其他已确认实际出库
网络在途期末 = 期初在途 + 实际发运进入在途 − 实际收货退出在途 ± 有依据的差异调整
```

内部调拨在全网络净增量为 0，运输途中仍只代表同一辆车。回购改变主体可控库存和权属，不能当作全国新增车辆。退货、车损、拒收等使用明确的差异事件，不靠修改期初数保持表面平衡。

### 7.3 原计划、当前计划、实际各保留一列

| 口径         | 用途                 | 变更时如何处理                                     |
| ------------ | -------------------- | -------------------------------------------------- |
| 周初发布基线 | 衡量是否兑现最初安排 | 保留原数量、去向和日期，版本不可覆盖               |
| 当前有效计划 | 安排接下来怎么做     | 根据授权变更替换未执行部分，并保存差异             |
| 执行实绩     | 证明已经发生什么     | 来自有效回执，晚到回执按实际业务时间归属并标注补录 |

到期队列类指标保留“截至哪个时点”的信息。到期未完成不能从分母删除。经确认的真实需求取消可以排除，但展示取消数量、原因与时间；供应不足导致的取消另列为履约损失，不能借此提高结果。

物流重试和任务拆分不增加需求。任务有根业务对象与替代关系，同一回执只应用一次。部分完成以车辆明细更新，批次状态由明细汇总。

### 7.4 缺数与空值

- 分母为零显示“不适用”，不默认显示 100%。
- 输入缺失显示“缺数据”，不填成 0 或自动沿用为当前值。
- 过期库存附最后更新时间，来源重新确认前不能形成可执行调拨。
- 推估序列与实际业务数据分别展示，不能合并为一条无标记的实绩曲线。
- 指标数据源未接入时显示所缺来源，不预填演示外的企业经营数值。
- 当前 `data/01_供给/按月总表.csv` 的2026-08/09 G/H为空，保留缺失；7月作为供给强度锚点时明确标为情景，不回填成8/9月实绩。

### 7.5 预警与下一步动作

| 预警             | 触发依据                                                | 建议动作                               |
| ---------------- | ------------------------------------------------------- | -------------------------------------- |
| 订单到店风险     | 确认的预计到达晚于原承诺，或到最晚操作时点仍缺来源/运力 | 查看调拨候选、替代班次，或提交交期例外 |
| 低库存           | 门店配置 DOS 低于该门店配置的有效最低目标               | 查看及时在途和净缺口，进入分货/调拨    |
| 高库存或库龄风险 | 高于有效最高覆盖，或超过该车型配置的库龄规则            | 查看可转出量与其他区域同配置需求       |
| 运输资源不足     | 同时段占用超过已确认可用资源，或装载模板不成立          | 回传受影响车辆，重排班次或分配         |
| 回购不能执行     | 权属、报价、资金或运输前置条件未成立                    | 分派对应责任人，不纳入落实车源         |
| 源店受损         | 调出后不足以保护有效订单或最低自由库存                  | 减少调拨、换来源或提出明确规则例外     |

这些规则引用已生效参数及版本，不杜撰通用的“低于7天就危险”等固定阈值。演示参数可以配置，但必须标明适用对象与生效窗口。

### 9.2 交互验收

1. 切换供给参考月，两个品牌和各车型供给同步重算，车型之和对回品牌；8/9月缺失不被自动填平。

3. 单车型草案修改后，共同路线资源占用更新；若挤占其他车型，显示具体冲突并反馈相关任务。
4. 切换双港口/仅西部，保持选定全国供给情景，改变入口、路线与容量；如批次承接不成立，单列未落实。
5. 区域和门店可下钻至车型；输入尚未细化时显示品牌原值与车型假设状态。
6. 运输与调拨共用锁车和资源记录，重复回执不重复记账；部分签收仅更新对应车辆。
7. 回购单、调拨单和运输单关联但不重复计算车辆，交易、物流与结算分别闭环。
8. 班次或交期变更保留原发布基线，实际兑现由回执核对，不能重写分母消除延误。
