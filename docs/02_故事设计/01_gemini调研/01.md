
在汽车供应链与终端分销领域，**“分车计划”（Vehicle Allocation）** 与 **“物流规划”（Outbound Logistics Planning）** 确实是同一套商业目标的两个侧面：

* **分车计划**解决的是**商业策略问题**：在有限或不稳定的车源下，“把什么车型、在什么时间、分给哪个地区的哪个门店，能实现收益最大化与客户满意度最佳？”
* **物流规划**解决的是**物理执行与约束问题**：在既定的分车需求下，“如何用最低的运输成本、最少的时间，在运力/路网约束下把车安全送达？”

在国际供应链波动（海运滚装船跳港、延期、VPC加装件缺料等）成为常态的背景下，这两个环节必须深度融合，形成“以约束为导向的动态分车”**与**“以柔性为核心的动态物流”。

以下是针对“港口/VPC到门店”场景中，需要重点考虑的核心关键点与解法分析：

---

### 一、 分车计划（Vehicle Allocation）的关键点

在供应链不稳定的环境下，传统“固定配额制”（按月/按季度给门店分车）会彻底失效，必须转向“动态预留+延迟决策”的策略。

#### 1. 优先级决策矩阵（Priority Matrix）

分车算法或规则必须明确不同订单的履行顺序：

* **实名订单优先（Firm Customer Orders）**：已付定金且绑定真实客户的订单优先级最高。
* **高利润/战略车型优先**：例如在中东市场，高配越野车或全新混动车型的利润和市场信号强，优先向重点区域分拨。
* **门店绩效与服务水平（CSI）绑定**：将分车权重与门店的周转率、客户满意度及销量目标达成率挂钩。
* **渠道公平与网络健康度（Network Health）**：必须设置“保底配额”，防止偏远地区或小门店长期无车可卖导致网络瘫痪。

#### 2. 延迟分车策略（Postponement Strategy）

* **取消“源头锁定”**：车辆在海外工厂出厂或海运途中，不提前绑定具体的终端门店，仅绑定到“国家/区域中心库”。
* **VPC/港口作为决策缓冲池**：将分车决策点后移至**车辆完成海关清关并在VPC完成PDI/加装之后**。此时车辆状态确定、质量合格，再根据最新的门店订单需求和运力情况进行瞬间匹配，极大减少“车到了门店却无人买，有人的门店却无车”的错配现象。

#### 3. 滚动式分车窗口（Rolling Allocation Window）

* 建立“3周滚动分车”机制：
* **W+1周（已锁定）**：已在VPC准备出港，运力已指派，不可变更。
* **W+2周（软锁定）**：已在海运途中或港口排队，根据最新零售订单调整地区比例。
* **W+3周及以后（预测态）**：仅作为门店销售预测和物流预定运力的参考。

---

### 二、 物流规划（Outbound Logistics）的关键点

干线与支线轿运车（Car Carrier）运输成本高、受装载率影响大，且受到公路运输法规与运力供给的严格限制。

#### 1. 轴辐式网络与节点布局（Hub-and-Spoke Network）

* **中央 hub（如吉达 VPC）**：负责海关清关后的集中整备、增值加装。
* **区域分拨中心（RDC，如利雅得/达曼中转库）**：将整船到港的大批量车辆干线运至RDC，再由RDC向周边城市门店进行短途二次分拨。这能有效降低单趟长途直送门店的空载和零散调度成本。

#### 2. 轿运车装载率与凑整优化（TL Optimization）

* 1辆标准双层轿运车可装载6–10辆整车。若某门店每周仅分配到2辆车，单独派车运输成本极高。
* **线路拼车（Consolidation）**：同干线方向的多个相邻门店必须联合规划物流线路（例如：同趟车装载“吉达-麦加-麦地那”沿线的3家门店车辆）。
* **车型混装优化**：轿运车的空间受车型尺寸（SUV、轿车、皮卡）限制，物流系统需要自动计算“SUV+轿车”的最优装载组合，确保空间与载重利用率最大化。

#### 3. 加装/PDI与物流干线的瓶颈协同（Sequencing & Scheduling）

* **加装件缺料（Accessories Shortage）风险**：在中东等市场，车辆在VPC需要加装大量属地化配件（如防撞杠、中控屏等）。如果分车计划分配了一批高配车，但加装零部件延迟，车辆就会卡在VPC无法出库，导致已预订的轿运车运力浪费。
* **物流驱动的PDI排期**：VPC的PDI作业顺序应反向由“物流出货计划”驱动（Pull System），优先检验和加装即将在下个班次发运的车辆。

---

### 三、 两者融合的核心交集与破局策略

当供应链不稳定（如船期延误2周，或者突然顺丰式到港大量车辆造成堆场暴库）时，单纯做分车或单纯做物流都会出问题。**破局的核心在于建立“基于约束的联合决策体系”**。

```
                  ┌──────────────────────────────┐
                  │ 供应链不确定性 (船期/缺料)    │
                  └──────────────┬───────────────┘
                                 │
                  ┌──────────────▼───────────────┐
                  │ VIN码全管道实时可视性 (VIS)   │
                  └──────────────┬───────────────┘
                                 │
         ┌───────────────────────┴───────────────────────┐
         │                                               │
┌────────▼─────────────┐                       ┌─────────▼────────────┐
│   分车计划 (商业)    │                       │   物流规划 (执行)    │
│ • 优先权矩阵         │                       │ • 轴辐式网络/RDC     │
│ • 延迟分车 (VPC缓冲) │◄─────────────────────►│ • 轿运车满载率 (FTL) │
│ • 动态订单匹配       │  约束与反馈 (S&OE机制) │ • PDI/加装节点协同   │
└──────────────────────┘                       └──────────────────────┘

```

#### 1. 基于约束的分车模型（Constraint-Aware Allocation Engine）

在生成分车计划时，**输入端不能只有“门店需求”，还必须输入“物流约束”**：

* *假设：利雅得A门店需要10辆车，但当前吉达到利雅得干线轿运车运力紧张，而到达曼的干线有剩余运力；同时达曼B门店也有类似需求。*
* **算法解法**：系统应动态调整分车优先级，优先将现有车源分拨给物流通畅或可顺路拼车完成的订单，避免分车计划写在纸上，却卡在仓库运不出去。

#### 2. VIN码级别的全管道可视性（Pipeline Visibility）

* 实现从“海运船舱 -> 港口堆场 -> VPC加装区 -> 轿运车装车 -> 在途 -> 门店卸货”全过程的 VIN 码级状态追踪。
* **运力与订单的动态重定向（In-Transit Re-routing）**：当轿运车已经在干线上行驶，如果某终端客户突然取消订单，或者另一地区出现极紧急的缺货，在物流中转库（RDC）阶段应具备动态更改目的地和接收门店的能力，实现物流响应的极致柔性。

#### 3. 建立“销售与运营执行”（S&OE）周例会与预警机制

* 传统的 S&OP（销售与运营规划）按月迭代，节奏太慢；在供应链不稳定期，需建立**周级别/日级别的 S&OE 机制**。
* 销售团队（确定分车优先顺序）、物流团队（反馈运力与VPC产能）、采购团队（反馈配件到位情况）每日基于系统数据对齐，快速解决突发瓶颈（如海运压港导致运力骤减时，重新调整全网分车路线）。

---

### 总结建议

在研究和设计该场景时，可以将切入点总结为以下架构：

1. **底层支撑**：VIN码全链路数据打通（从港口到门店）。
2. **中间枢纽**：以 VPC/RDC 为“蓄水池”实施**延迟分车**，避免早期锁定造成的库存呆滞。
3. **上层算法**：将“商业优先级（订单/利润）”与“物理约束（轿运车装载率/线路成本/加装产能）”输入同一个算法引擎，生成**兼顾商业收益与物流可行性的动态分车发运表**。
