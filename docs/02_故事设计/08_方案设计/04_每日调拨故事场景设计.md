# 每日调拨故事场景设计

日期：2026 年 10 月 5 日。本文用于梳理每日调拨的业务背景、角色、决策过程与演示故事，作为后续详细剧本和页面设计的依据。

**核心故事：新的订单出现后，调拨员利用全网已有车源，以合理的代价兑现交付承诺，同时保护调出门店的销售能力。**

本文沿用项目中“吉达单港、供给受限”的演示背景。人物、订单和数量均为故事设定，不代表 ALJ 实际运营。建议采用“早晨订单池 + 企业大单”的主线，穿插高价值急单、普通订单和执行异常；具体车源数量、报价和计算结果在后续详细剧本中统一确定。

## 1 场景定位与前后关系

周度分车决定一批新车如何分配给订单和门店补库；物流方案把分车结果变成到店安排。计划发布后，新增订单、客户取消、运力延误和门店库存错配仍会持续发生，每日调拨负责接住这些变化。

| 环节 | 主要问题 | 与每日调拨的关系 |
| --- | --- | --- |
| 周度分车 | 本批车辆分给哪些订单和门店 | 提供已有分配、未满足订单、补库占用和自由车源 |
| 到店物流 | 车辆如何按期送到最终门店 | 提供班次、运输状态、到店时间和可调整范围 |
| 每日调拨 | 今天的需求变化如何利用已有车源满足 | 调整受影响的车辆与任务，记录来源端损失和补回安排 |
| 下一轮分车 | 后续供给需要优先补哪些缺口 | 接收未满足订单、被借用补库和已确认的调拨结果 |

每日调拨不增加全国实物车辆总量。内部调拨改变位置和业务归属；授权车商回购改变权属与总部可调度范围，不能同时记为新增进口供给。

已分给门店但暂存在 VPC 的车辆，仍保留原门店归属。它们属于可申请改派的候选，不能因为物理位置在 VPC 就视为公共自由库存。

## 2 每天早晨的业务起点

每天 08:30，调拨员 Sara 打开工作台，看到新增订单、昨日未解决的缺口、取消订单释放的车辆，以及可能影响交付的异常。

她首先需要回答：“今天哪些必须处理，哪些已有覆盖，哪些有现成解法，哪些需要我做取舍？”

Agent 先核对订单与车辆状态，排除已经被现货或可靠在途覆盖的重复申请，再按交期、订单价值和缺口整理待处理事项。对于库存积压或取消订单，先寻找可匹配的真实需求，再判断是否需要移动车辆。

| 场景 | 典型问题 | 主要判断 |
| --- | --- | --- |
| 普通订单有单无车 | 本店没有客户指定配置 | 同城调车、顺路拼载，还是协商替代配置或交期 |
| 高价值急单 | 交期紧，指定配置不能替换 | 增量成本是否值得，哪个车源影响最小 |
| 企业大单 | 单店库存不足，需要多地集结 | 能否在整单交付窗口内组合车源，是否需要回购 |
| 门店库存错配 | 有的店积压，有的店缺货 | 调出后源店是否安全，目标端是否有真实需求 |
| 取消与交付异常 | 车辆释放，或原车无法按期到达 | 能否重新匹配需求，是否需要调整已有运输 |

## 3 参与角色与责任

| 角色 | 主要责任 |
| --- | --- |
| 调拨员 Sara | 管理每日需求池，比较方案，确认权限内的调拨并追踪结果 |
| 销售与目标门店 | 确认订单、承诺交期、替代配置和客户接受情况，落实接车安排 |
| 调出门店 | 确认可释放车辆、车况、现有订单占用和调出后的销售影响 |
| 供应链负责人 | 决定影响补库、区域保障或安全线的例外，确认补回安排 |
| 物流负责人 | 确认承运能力、班次、报价、保护条件和到店时间 |
| 商务与财务 | 确认授权车商回购的报价、权属、信用和结算条件 |
| Agent | 整理需求，匹配车源，比较方案，解释双端影响并持续处理变化 |

## 4 故事主线与六个场景

建议以“一个早晨的订单池”串起整个故事。企业大单提供主要冲突，高价值急单和普通订单展示不同的取舍，最后用一次异常说明方案如何随执行变化更新。

### 场景一 识别真正的订单缺口

Sara 向 Agent 提出：“先整理今天必须处理的订单，确认现货和在途有没有覆盖。”

Agent 核对订单有效性、配置、已绑定车辆和预计到店时间。有些申请已经有可靠配送安排，有些订单仍缺车，还有些虽然分到车，却无法按承诺日期到店。

这一幕输出按紧急程度排序的需求池，让 Sara 明白今天真正需要决策的事项。

### 场景二 企业大单打破原有安排

新增一笔要求在明确日期内集中交付的 **80 台 Hilux 企业订单**。80 台仅作为本版故事示例，不作为已验证的数据基线。

本地库存不足，Agent 同时查看 VPC 自由库存、本批尚未发运且允许改派的补库车辆、直营门店可释放库存，以及授权车商愿意出售的合格车辆。

Agent 将订单作为整体组合车源和物流，展示可按期交付数量、剩余缺口、受影响的原计划和需要确认的事项。已被可靠覆盖的车辆先保留，不为追求单一车源而全部重排。

### 场景三 最近的车源无法直接调走

某家邻近门店有同配置车辆，但调走后会跌破安全库存；另一家稍远门店库存较充足，可能更适合提供车辆。

Agent 展示两家门店的同配置自由库存、有效订单、销售速度、调出后覆盖周数，以及下一批确认到货。覆盖计算沿用前文的周口径，并考虑交付时点之前的预计消耗与及时在途。

Sara 能看到目标订单获得什么，也能看到源店失去什么。安全线以下的调出必须显式列为例外，交由负责人决定，并明确补回或补偿安排。

### 场景四 急单和普通订单得到不同解法

同时出现一笔指定配置的高价值急单和一笔普通订单。

高价值急单的候选车源能够赶上交期，增量运输费用相对于保单收益合理，Agent 推荐调拨，并比较不同来源端影响。

普通订单如果使用跨区专车，会消耗过多利润。Agent 给出既有班次拼载、本地替代配置、等待已确认到货等方案，并说明各自的到店日期和费用。销售与客户确认替代配置或新交期后，方案才形成新的交付承诺。

这一幕体现逐单取舍：同一套系统可以建议调车，也可以建议等待、转化，或明确报告当前无法满足。

### 场景五 确认方案并形成执行任务

Sara 确认权限内的调拨；供应链负责人确认改派和例外；商务、财务完成回购条件确认；物流负责人落实班次、保护条件和收货窗口。

执行前，Agent 再次核验订单有效性、车辆锁定和库存版本，确认同一车辆未被重复占用。完成条件确认后，锁定具体车辆并生成关联的调拨单、回购单和运输任务。

回购车辆可以从授权车商直接运往目标门店或所属交付点，无须先返回 VPC。目标点仍需具备实际接车、整备和交付能力。

### 场景六 一次异常触发局部调整

演示中加入一次候选车辆在确认前被源店售出，或承运班次延误的事件。

Agent 撤回受影响的失效建议，重新匹配相关订单，说明新的车源、到店日期、费用和待确认项。未受影响的有效绑定和任务继续保留。

签收后更新车辆位置和库存，记录被借用补库的缺口并回写下一轮分车。回购车辆的财务结算继续独立跟踪，车辆到店不等于结算完成。

## 5 车源搜索与方案比较

| 候选车源 | 必须核验的条件 |
| --- | --- |
| 本店现货与既有到店安排 | 是否已覆盖订单，配置与到店时间是否满足要求 |
| VPC 自由库存 | 是否真正未占用，是否可释放，整备和配送是否落实 |
| 本批未发运的补库车 | 是否允许改派，原门店影响和补回安排是否明确 |
| 直营门店自由库存 | 是否已有客户占用，车况是否合格，调出后是否安全 |
| 可调整的在途车辆 | 是否处于允许改派的节点，承运是否可执行，是否损害原承诺 |
| 授权车商库存 | 是否愿意出售，报价、权属、车况和交易条件是否成立 |
| 下一批确认到货 | 是否有可靠车源与预计到店日期，客户是否接受等待 |

这是候选检查范围，不能直接等同于成本最优顺序。先排除权属、配置、交期、车况和运输不成立的方案，再比较合格方案的总增量成本及其对订单和来源端的影响。

Agent 的判断围绕四个问题展开：

1. 有没有合格且可占用的车源？
2. 能不能在客户接受的时间内交付？
3. 保住订单、避免损失所获得的收益，是否值得新增的代价？
4. 调出门店和原计划能不能承受这次变化？

成本比较应覆盖回购价差或取得车源的增量费用、运输、装卸、整备、让利，以及来源端影响，避免只比较运费。回购价格与订单利润须采用一致口径，不能把整车购入成本重复扣进已经包含进货成本的毛利。

## 6 需要明确的业务边界

- **有库存不等于可调。** 已绑定客户、冻结、车况不合格或未取得交易条件的车辆，不能进入可执行清单。
- **原门店归属不能静默消失。** 已分配补库的车辆被改派时，要记录受影响门店、数量、授权决定和补回安排。
- **安全线与目标水位分别判断。** 低于目标表示尚有补库需求；跌破最低安全线的调出需要例外决定。
- **等待按到店日期判断。** 船舶到港还需考虑清关、整备、运输和收货窗口，不采用固定天数直接决定是否等待。
- **车型利润不是单独的驳回依据。** 普通订单也要逐单比较成本、失单损失和可行替代方案。
- **配置变化与延期需要客户接受。** Agent 可以提出建议，销售负责取得确认。
- **调拨、回购和运输分别记录。** 调拨说明为什么移动，回购记录交易与结算，运输记录如何送达；三者关联同一车辆。
- **同一车辆和订单只能计量一次。** 改派、回购、在途与下一轮分车共享占用记录，避免重复覆盖需求或重复统计供给。

## 7 每日处理清单与决策说明

| 处理结论 | 含义 | 下一步 |
| --- | --- | --- |
| 可执行 | 车源、权属、运力和收货窗口已经落实 | 确认占用并执行运输任务 |
| 待业务确认 | 改变补库、客户承诺或安全保障 | 由对应负责人确认 |
| 待回购确认 | 报价、车况、权属或结算条件尚未落实 | 完成交易条件后再执行 |
| 建议替代或等待 | 存在更合理的配置或到货方案 | 销售取得客户接受 |
| 当前无法满足 | 缺少合格车源、可靠交期或运输能力 | 明确缺口并升级处理 |

每笔决策说明至少包含订单需求、具体车源、预计到店日期、完整费用、源店影响、备选方案，以及待确认事项和责任人。不同订单竞争同一车辆时，要统一分配，不能分别给出互相冲突的“最优建议”。

执行结果另行记录待发运、在途、已签收、取消、部分完成或失败等状态；处理结论不能替代运输回执。

## 8 故事需要证明的价值

这条故事需要让观众看到：Agent 可以识别真实缺口，为企业大单组合车源，对急单与普通订单采用不同方案，并同时解释目标端收益和来源端损失。

演示结果重点展示以下内容：

- 原先无法按期满足的订单中，有多少获得了可执行方案。
- 相比可行备选方案，新增了多少费用，保护了多少订单贡献和避免损失。
- 哪些门店补库被调整，是否出现安全线例外，补回安排是否明确。
- 哪些订单仍无法满足，以及谁负责下一步处理。
- 异常发生后，哪些建议被撤回，哪些车辆和任务需要重新安排。

所有数量和费用都应能追到具体订单、车辆和方案版本。回购尚未确认、客户尚未接受或运力尚未落实的方案，不能提前计入已完成履约结果。
