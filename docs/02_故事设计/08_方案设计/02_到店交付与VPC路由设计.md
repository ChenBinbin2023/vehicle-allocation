# 到店交付与 VPC 路由

## 核心方案

产品内 `/delivery-plan` 引用指定分车快照。**单港、双港最终都分货到门店**；VPC 是物理暂存或服务节点。具备停车、接车及整备条件的门店仍受当批容量限制，同店可以“部分直送 + 部分 VPC 暂存 + 后续分批到店”。VPC 暂存不改变门店归属，也不等于已到店。

## 来源与情景参数

- `data/04_运力/路线主数据.csv`、`门店路线映射.csv`、`场景路线运力.csv` 提供 36 条城市路线、门店映射、单/双港场景周运力和整趟报价。
- 同城门店共享一条路线的周运力，只扣减一次；不能把城市路线额度复制给每家门店。单港、双港是独立情景，不合并运力。
- 停车余量 = 门店总库容 − **所有品牌**的实物库存。首批与后续单次接车量默认按周销速一半向上取整，并受停车余量限制；直营直送、授权经 VPC、后续时段与 VPC 容量均是可编辑的**情景假设**，不当作数据中已有的接车/PDI事实。
- 到店时间按源运输小时数折天，再配合情景接车时段；源路线仅到城市级节点，末端与整备条件仍需实际确认。
- 源报价按整趟装载量计费，非满载向上取整。同城门店共用趟次，已知干线费用按数量分摊。缺少 VPC、整备和末端报价时，只列干线小计，完整成本与节省额保持待确认。

## 计算与异常

先保护订单的路线额度，再安排补库；直送不超过首批接车与停车余量。剩余车辆先扣共享 VPC 容量，再按门店后续时段分批到店。路线或 VPC 容量不足列“未落实”；无接车时段列“待排程”，不生成确定 ETA。

服务 VPC、实际经由 VPC、最终门店分别记录。已有 VPC 车源应从当前位置起运；`data` 没有独立 VPC 库存明细，当前不生成额外 20 台车源或虚构港口运输段。

## 当前默认模拟的结论

沿用丰田 1800 台分车、不含新订单，使用默认接车情景：单港直送 **557 台**、经 VPC **1070 台**、未落实 **173 台**；已落实中 **8 台**待排到店时段。双港直送 **558 台**、经 VPC **1242 台**、未落实 **0 台**，其中 **20 台**待排程。差异来自源路线周运力及运输时间，不能仅凭停车场资格把全部分车改成直送。

GUI 提供“路线地图 / 到店路线 / 港口比较 / 到店批次”、接车条件、VPC 与补充费用参数；重跑保留旧快照及其分车引用。验收每轮满足“分车 = 直送 + 经 VPC + 未落实”，待排程是已分配 VPC 量的子集。模拟不自动发布，也不生成真实签收。

地图按共享城市路线汇总，再下钻计划到店批次；无真实承运班次号。补充港口/PDI/末端/VPC/暂存情景费率后可算预算；未知费用或未落实路线仍保持完整成本待确认。完成物流后可进入 `/profit-analysis` 分析订单、车型、门店的贡献利润，见 [物流地图与利润分析设计](05_物流地图与利润分析设计.md)。
