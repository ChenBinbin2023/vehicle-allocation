# 吉达单港供应链 Agent 前端 Demo 重构设计

> 状态：待书面评审  
> 日期：2026-10-04  
> 实现目录：`frontend/`  
> 业务故事依据：`docs/02_故事设计/06_新故事设计/01_吉达单港危机下的分车_物流与调拨Agent故事线.md`

## 1. 目标

将现有 ATLAS 前端 Demo 完全替换为一条干净的新故事线。新 Demo 保留现有灰白三栏视觉风格、Session、本地持久化、CUI 输入与 GUI 画布协作方式，但删除旧周度分货、全国物流、每日调拨、周末复盘、教学算例和旧故事导航。

演示由 CUI 中的 Skill 串联。用户输入 `/` 选择 Skill，输入框自动带出推荐提示词，按回车后 CUI 流式输出任务规划、数据读取、校验、分析和结论；中间 GUI 与 CUI 同步，以一个个 block 的方式逐步生成。每个 Skill 对应一段完整用户故事和一张可继续交互的 GUI 工作台。

成功标准：

1. 整条故事只围绕吉达单港和同一批 1,800 台车辆展开；
2. 船次分车与物流执行构成第一阶段，每日调拨构成第二阶段；
3. 每一段故事必须从 CUI Skill 发起；
4. GUI 不能通过导航点击偷偷启动业务动作；
5. 五个 Skill 共享同一套 VIN、订单、库存、运力和执行状态；
6. 所有演示数据都明确属于模拟数据；
7. 旧业务和教学入口从产品界面及运行状态中完全删除。

## 2. 非目标

- 不接入真实后端、数据库、物流系统或大模型；
- 不实现真实的数学优化求解器；
- 不保留旧故事作为隐藏入口或教学模式；
- 不引入新的视觉品牌、在线字体或地图服务；
- 不把所有可能的供应链异常都纳入首版；
- 不允许 GUI 操作绕过 CUI 启动下一段故事。

## 3. 演示受众和呈现原则

Demo 以管理层和客户演示为主，以业务操作可信度为辅。

主层级需要在短时间内说明：发生了什么、Agent 做了什么、为什么这样决策、结果如何。关键指标可以下钻到 VIN、订单、VPC、路线和板车，让业务人员确认方案不是静态图表或无法解释的黑箱。

视觉上延续现有 ATLAS：

- 灰白背景和克制的绿色主色；
- 琥珀色表达风险、阻断和待确认；
- 左侧故事进度与 Session；
- 中间 GUI 业务画布；
- 右侧 CUI；
- 紧凑但不拥挤的卡片、表格、路线图和状态标签；
- 桌面优先，同时保留移动端可演示性。

## 4. 两个业务阶段

### 4.1 第一阶段 船次分车与物流执行

时间范围为滚装船到港前 14 天至到港后 2–3 天。

该阶段解决：

- 达曼港关闭后，吉达单港会产生什么影响；
- 1,800 台车中哪些已经服务预订订单，哪些用于 VPC 库存补充；
- 如何在单港约束下优化路线、板车和交期；
- 车辆到港后如何在 2–3 天内完成清关、PDI、装车、发运和签收；
- 如何形成后续每日运营使用的 VPC 库存基线。

### 4.2 第二阶段 每日订单调拨

时间从到港后第 3 天开始。第一阶段车辆已经到达订单交付点或吉达、利雅得、达曼 VPC。

各 4S／5S 店每天提交订单，Agent 从 VPC、门店和授权车商库存中选择车源，生成正常发货、跨区调拨、门店调拨、回购、配置转化、等待或偏远拼单方案。

第二阶段不能提前运行。只有第一阶段完成并生成库存基线后，才能执行每日调拨。

## 5. 五个 Skill

### 5.1 `/crisis-brief`

用户故事：供应链负责人需要理解单港进入对未来船次的影响，并确认后续计划的决策范围。

默认提示词：

> 分析两周后抵达吉达港的 1,800 台车辆，在达曼港关闭情况下的供需、库存和运输影响。

CUI 流程：

1. 读取船次和 1,800 台 VIN；
2. 读取已预订订单和三大 VPC 库存；
3. 对比双港与吉达单港网络；
4. 识别东向运力、绕行和重复装卸风险；
5. 输出危机判断和下一步分车建议。

GUI Block：

1. 船次标题和 T-14 倒计时；
2. 1,800 台车型与配置结构；
3. 订单需求与 VPC 补货缺口；
4. 双港和单港路线对比；
5. 东向运力压力和风险清单；
6. Agent 建议的决策范围。

### 5.2 `/vessel-allocation`

用户故事：分车负责人需要先保护已预订订单，再用剩余车辆补充三大 VPC，并保留机动能力。

默认提示词：

> 为本船 1,800 台车制定分车计划，优先保护已预订订单，再补充三大 VPC 库存，并保留必要机动量。

CUI 流程：

1. 冻结不可分配车辆；
2. 锁定企业、零售和高利润订单；
3. 计算三大 VPC 的车型补货缺口；
4. 保护区域最低库存；
5. 生成车辆归属草案；
6. 检查数量守恒和冲突；
7. 输出待物流校验的分车版本。

GUI Block：

1. 可分供给和冻结车辆；
2. 订单池与补货池总览；
3. 企业、零售、高配和高利润订单；
4. 吉达、利雅得和达曼 VPC 补货；
5. 区域覆盖变化；
6. VIN 分配明细；
7. 未满足需求和待审批例外；
8. 分车草案版本。

业务参数可以在 GUI 调整，但修改后当前结果进入 `stale` 状态，必须从 CUI 重新运行 `/vessel-allocation` 才能生成新版本。

### 5.3 `/delivery-plan`

用户故事：物流负责人需要把分车草案转成在吉达单港条件下可执行的路线和板车计划。

默认提示词：

> 基于当前分车草案，设计吉达单港条件下的运输和配载计划，比较订单车、补货车及偏远地区的物流方案。

CUI 流程：

1. 读取分车草案和车辆释放时间；
2. 按方向、交期和保护等级聚类；
3. 生成板车配载和运输线路；
4. 检查司机、班次、装载率和收货窗口；
5. 比较不同订单类型的物流方案；
6. 将不可执行约束回压给分车计划；
7. 输出可发布的联合计划。

GUI Block：

1. 港口 D1–D3 释放节奏；
2. 西部短链、利雅得中轴、东部直达、利雅得截流和达曼安全库存；
3. 板车和配载计划；
4. 路线容量和装载率；
5. 企业大单、高配车、普通订单、VPC 补货和偏远拼单方案；
6. 成本、时效和装卸次数比较；
7. 物流回压造成的分车调整；
8. 联合计划发布检查。

### 5.4 `/arrival-execution`

用户故事：物流负责人需要在车辆到港后执行联合计划，并在 2–3 天内形成新的 VPC 库存基线。

默认提示词：

> 执行本船到港后的清关、PDI、装车和配送计划，并跟踪车辆在到港后 2–3 天内到达订单交付点或 VPC。

CUI 流程：

1. 读取已发布联合计划；
2. 接收滚装船到港和清关事件；
3. 按批次释放车辆；
4. 匹配已确认板车；
5. 跟踪发运、在途和签收；
6. 识别延误和局部异常；
7. 只重排受影响车辆；
8. 建立新的 VPC 库存基线。

GUI Block：

1. T0 至 T+3 执行时间轴；
2. 清关和 PDI 释放进度；
3. 港口待装车辆；
4. 板车班次执行板；
5. 全国在途路线；
6. 订单车交付状态；
7. 三大 VPC 到货进度；
8. 异常和局部重排；
9. 1,800 台最终状态守恒；
10. 每日运营库存基线。

### 5.5 `/daily-rebalance`

用户故事：每日调拨员需要根据各门店新订单，从现有网络中找到最合适车源并安排发货。

默认提示词：

> 分析今天各门店提交的订单，从 VPC、门店和授权车商库存中寻找最合适车源，并生成发货、调拨或回购方案。

该 Skill 可以按经营日重复运行。

CUI 流程：

1. 读取今日订单池；
2. 读取三大 VPC 和门店可售库存；
3. 排除已锁定、冻结和无调度权车辆；
4. 为每笔订单生成候选车源；
5. 比较时效、成本、利润和来源端影响；
6. 对企业大单进行组合求解；
7. 判断是否需要门店调拨或授权车商回购；
8. 输出今日执行和审批事项。

GUI Block：

1. 今日订单池；
2. 订单优先级和承诺时间；
3. VPC 正常发货方案；
4. 候选车源网络；
5. 企业大单集结方案；
6. 高利润订单调拨方案；
7. 普通订单转化、拼载或等待建议；
8. 偏远地区集单配送；
9. 门店调出影响；
10. 授权车商回购条件；
11. 今日待审批事项；
12. 发货、签收和库存更新。

## 6. Skill 运行协议

### 6.1 发起方式

1. 用户在 CUI 输入 `/`；
2. 菜单展示当前可执行和不可执行的 Skill；
3. 不可执行 Skill 显示缺少的前置条件；
4. 用户选择 Skill 后，输入框自动填入推荐提示词；
5. 用户可以编辑提示词；
6. 按回车才正式启动。

### 6.2 运行状态

```text
ready
→ planning
→ reading
→ validating
→ analyzing
→ waiting_for_decision 可选
→ completing
→ completed
```

每个阶段同时追加 CUI 事件和推进 GUI Block。CUI 输出使用流式文本；GUI 当前 Block 使用骨架、进度点和逐项内容，完成后进入可交互状态。

### 6.3 GUI 同步规则

```text
CUI 读取船次
→ GUI 显示船次摘要

CUI 锁定订单车辆
→ GUI 显示订单池

CUI 计算 VPC 缺口
→ GUI 显示补货分配

CUI 校验运输能力
→ GUI 显示线路容量

CUI 发现阻断
→ GUI 显示异常和待审批项

CUI 输出最终建议
→ GUI 完成当前工作台
```

已经出现的 Block 保持稳定。新的 Block 在下方依次加入，不刷新整个页面。

### 6.4 决策和下一步

GUI 可以完成当前 Skill 内的筛选、下钻、参数调整和确认动作。运行结束后，CUI 显示下一 Skill 建议，但不自动运行。用户必须再次通过 `/` 发起下一段。

运输维度：

### 7.3 `SkillRun`

每次运行保存：

- 运行 ID、Skill 命令和用户提示词；
- 经营日期和输入版本；
- 运行状态；
- CUI 事件；
- GUI Block 及已显示数量；
- 用户决策；
- 结果版本；
- 下一 Skill 建议。

运行结果是不可变快照。后续参数变化生成新版本，不覆盖历史结果。

### 7.4 GUI Block

每个 Block 保存：

- Block ID、类型、标题和状态；
- 所属 SkillRun；
- 输入版本；
- 业务数据；
- 支持的交互；
- 来源引用。

状态包括：`queued`、`streaming`、`ready`、`action_required`、`stale`、`error`。

## 11. 错误和冲突处理

- 业务参数变化后，相关结果标记为 `stale`；
- 同一 VIN 被多个需求占用时阻断发布；
- 路线容量不足时回传受影响需求，不缩减总量掩盖问题；
- 已发运车辆不能被普通调拨重新占用；
- 未完成权属确认的授权车商库存只能作为候选；
- 重复签收按事件编号去重；
- 单个 Block 失败时保留前面已经完成的 Block；
- 运行失败显示原因和重试入口；
- 切换 Session 时，运行状态保存在原 Session；
- 刷新后未完成运行恢复为暂停状态，由用户继续。

## 12. 测试策略

### 12.1 单元测试

- 1,800 台在需求和运输两个维度守恒；
- VIN 不重复占用；
- 订单优先级和 VPC 安全库存；
- 单港路线选择；
- 物流约束回压；
- 到港执行状态转换；
- 签收事件去重；
- VPC 库存基线生成；
- 每日订单候选车源；
- 调出门店安全水位；
- 授权车商回购条件；
- Skill 前置条件和结果失效。

### 12.2 浏览器测试

- `/` 菜单和提示词自动填充；
- 五个 Skill 的顺序运行；
- CUI 文本逐条输出；
- GUI Block 逐个出现；
- 运行暂停、恢复和 Session 切换；
- 参数变化使结果失效；
- 第一阶段完成前不能运行每日调拨；
- 企业大单、高利润订单、普通订单和回购流程；
- 桌面和移动布局；
- 页面刷新后的状态恢复；
- 左侧进度点击不能启动未执行 Skill。

## 13. 验收标准

1. 新 Session 打开时，中间 GUI 不展示旧业务数据；
2. 用户通过 `/` 可以依次找到五个新 Skill；
3. 选择 Skill 后自动带出提示词，只有回车才启动；
4. 每个 Skill 的 CUI 和 GUI 都以流式方式推进；
5. 第一阶段完整覆盖 T-14 至 T+3；
6. 1,800 台中订单池和库存补充池守恒；
7. 单港影响和优化路线在 GUI 中可被清楚比较；
8. 到港执行完成后生成新的 VPC 库存基线；
9. 每日调拨只能基于该库存基线运行；
10. 每日调拨支持 VPC 发货、门店调拨、企业集结和授权车商回购；
11. 已完成阶段可以回看，但未开始阶段不能由左侧导航启动；
12. 旧故事、教学算例和旧 Skill 不再出现在界面或运行状态中；
13. Session 隔离、刷新恢复和移动端布局继续有效；
14. 全部单元测试、类型检查、构建和浏览器测试通过。
