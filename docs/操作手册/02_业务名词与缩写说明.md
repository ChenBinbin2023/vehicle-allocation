# ALJ 丰田与雷克萨斯分车调拨业务名词说明

ALJ Motors（Abdul Latif Jameel Motors，阿卜杜勒·拉蒂夫·贾米尔汽车）在沙特开展丰田（Toyota）和雷克萨斯（Lexus）的进口、分销业务，并运营零售与物流网络。这使分车与调拨需要同时回答三个问题：进口车辆怎样分给订单和门店，车辆怎样运到交付地点，以及后续出现缺货时怎样取得合适车源。[ALJ 官方业务介绍](https://alj.com/en/our-people/peter-aberle/)

本说明沿着 **认识销售网络 → 看清供给与库存 → 优先满足订单 → 余车补库 → 到店运输 → 每日匹配车源 → 比较交期与利润 → 生成执行草案** 的业务顺序解释名词，配合[操作手册](01_吉达港整船分车与每日调拨操作手册.md)使用。

下文的吉达单港、2,500 辆本船、79 家门店、库存目标、采购报价和运输时间，均属于**本项目的 ALJ 丰田／雷克萨斯模拟场景**，不是 ALJ 当前实际船量、渠道政策或报价。文中“示例门店”的凯美瑞库存是独立教学算例；LX 急单则取自当前演示页面。

## 一 先认识 ALJ 在卖什么以及卖给谁

先确定经营主体和车辆产品，再区分销售渠道、交易账户与实体门店。同样一辆车，供给方卖给授权车商，与直营店卖给终端客户，收入和库存归属的口径不同。

### 经营主体与车辆产品

| 名词 | 含义 | 放到 ALJ 丰田与雷克萨斯场景中理解 |
| --- | --- | --- |
| ALJ／ALJ Motors | ALJ 为 Abdul Latif Jameel；本项目的汽车业务主体为 Abdul Latif Jameel Motors。 | 从沙特进口分销方的视角看丰田和雷克萨斯供给，再衔接渠道销售与交付。 |
| 品牌 | 产品所属的品牌。 | 丰田与雷克萨斯分别统计；丰田有余车，不能直接抵消雷克萨斯订单缺口。 |
| 车型 | 品牌下的产品系列。 | 丰田凯美瑞（Camry）、海拉克斯（Hilux）和雷克萨斯 LX 是不同车型，供给、库存与需求分别匹配。 |
| 配置／颜色 | 同一车型进一步细分的版本和外观要求。 | 当前每日演示中的 LX 需求指定 VIP（Very Important Person，贵宾）四座版、珍珠白；找到其他配置或颜色的 LX，不等于已找到合格车源。 |

### 从销售渠道到具体门店

| 名词 | 含义 | 放到 ALJ 丰田与雷克萨斯场景中理解 |
| --- | --- | --- |
| 直营门店 | 由经营主体直接管理的销售网点。 | 项目把部分丰田／雷克萨斯销售需求放在直营网络中，补库利润按零售收入测算。 |
| 授权门店／授权车商 | 独立经营、通过授权渠道取得车辆的销售方。 | 项目中 ALJ 向授权渠道供车时看批发收入；缺货时从授权车商买车，则是另一笔采购交易。 |
| L2 | Level 2，第二级；本文指项目中的二级授权车商渠道。 | 模拟网络采用 34 家直营店、45 家 L2 门店，共 79 家；这些数量与 L2 层级均按项目数据理解。 |
| 交易身份／账户 | 用于交易、结算和汇总的主体。 | 模拟数据让直营门店共用一个结算身份，L2 分别设身份；一个账户的汇总与其门店明细不能相加。 |
| 门店／销售网点 | 实际销售、接车或交付的地点。 | 利雅得某店缺凯美瑞，需要查这家店的库存与订单，不能仅看其结算账户是否有车。 |
| 大区 | 用于服务、汇总与调度的地理范围。 | 项目划分西部、中部、东部、北部、南部；同一车型在全国有库存，也可能在需求所在大区缺货。 |

项目中丰田覆盖全部 79 家门店，雷克萨斯只在设定具备品牌经营资格的 20 家门店参与计算。这是模拟网络的经营资格设定，不能理解为真实网点统计，也不能给不经营该品牌的门店硬分车辆。

## 二 再判断车在哪里以及哪些车能用

面对利雅得门店的订单，先查车源位置，再识别具体车辆，最后核对占用、车况和归属。停车场里看得到车，只说明有实物，还不能说明可以拿来满足新订单。

### 从车源位置找到具体车辆

| 名词 | 含义 | 放到当前场景中理解 |
| --- | --- | --- |
| 本船供给／整船总量 | 当前进口船次纳入分配的车辆数量。 | 本船模拟共 2,500 辆丰田和雷克萨斯，按吉达单港情景规划；本船有车不表示已完成清关或已到门店。 |
| 车源点／来源门店 | 可以提供车辆的地点或销售方。 | 每日调拨会检查 VPC、区域门店和授权车商；车源类型决定后续是配送、内部调拨，还是采购。 |
| VPC | Vehicle Processing Center，车辆处理中心，衔接暂存、整备和配送。 | 项目设置吉达、利雅得、达曼 VPC 节点。车辆存放在 VPC，也可能早已分给某家门店。 |
| 区域中转中心 | 衔接干线运输与区域配送的节点。 | 补库物流中用于把吉达方向的车辆分段送往门店；部分中心是模拟地点，不表示真实处理能力已获确认。 |
| 服务 VPC／实际经由 VPC | 前者是服务门店的中心，后者是该车实际经过的中心。 | 利雅得门店有服务中心，不表示从其他门店调来的每辆车都必须绕行该中心。 |
| 库存编号／VIN | 单车追踪标识；VIN 全称为 Vehicle Identification Number，车辆识别代号。 | 同一笔两辆 LX 的订单，要分别对应两辆候选车；当前演示编号是模拟标识，不能当作已核验的真实 VIN。 |

### 从实物库存判断可用库存

| 名词 | 含义 | 用示例门店的凯美瑞理解 |
| --- | --- | --- |
| 实物库存 | 当前实际停放在该地点的全部车辆。 | 假设利雅得一家丰田门店停着 30 辆凯美瑞，这 30 辆都是该店凯美瑞实物库存。 |
| 订单锁定库存／已占用库存 | 已绑定客户订单或其他既有承诺的车辆。 | 其中 8 辆已为客户锁定，不能再卖给新客户或拿去补另一家店。 |
| 冻结库存 | 因质检或其他限制暂时不能使用的车辆。 | 另有 2 辆等待质检处理，虽然停在店内，也不能按可用车源分配。 |
| 自由库存／可用库存 | 未被占用、未冻结且符合本轮使用条件的库存。 | 此例剩余 20 辆可以参与自由销售或进一步评估调拨；不是全部 30 辆都可用。 |
| 在途库存 | 正在运往目标地点、尚未到达的车辆。 | 运往利雅得门店的凯美瑞单独列为在途；评估未来是否够卖，要看它何时到店，不能提前加进当前实物。 |
| 门店归属 | 车辆在业务上已分给哪家门店、承担什么用途。 | 某辆凯美瑞暂存在 VPC，但已分给达曼门店补库，不能因为它停在中心就直接供利雅得使用。 |
| 库龄 | 车辆在库存中停留的时间。 | 一辆凯美瑞已存放 60 天，说的是这辆车的滞留时间；与“这批库存还能卖几周”不同。 |

**示例库存关系：30 辆实物 = 8 辆锁定 + 2 辆冻结 + 20 辆自由库存。** 注水补库主要看后者，停车空间则需要看全部实物车辆，并合并其他品牌占用。

## 三 本船先保障已经卖出的订单

ALJ 的进口车辆既要兑现已售订单，也要支撑门店后续销售。当前演示先明确本船分配范围和预留，再保障已确认订单，最后把剩余车辆交给补库环节。

| 名词 | 含义 | 本船模拟中的对应业务 |
| --- | --- | --- |
| 预留车辆／预留比例 | 按策略保留下来、不直接进入普通分配的车辆及比例。 | 默认按 2,500 辆的 10% 预留，即 250 辆；不是已经分给客户的订单车。 |
| 已售未交付订单／订单需求 | 已确认客户购买、但尚未完成交付的需求。 | 本船默认对应 1,694 辆订单需求，需要核对每个车型，不能只用全船总量判断够不够。 |
| 分车 | 将车辆供给分给订单或门店，确定用途和归属。 | 本船中的一辆凯美瑞可以分给某笔客户订单，也可以用于某店补库，两种用途分别记账。 |
| 订单分车 | 给已确认订单分配车辆。 | 默认本船成功分配 1,642 辆订单车；这些车不再进入自由库存补库水位。 |
| 订单满足率 | 已分配订单车辆数占订单需求车辆数的比例。 | 此轮为 1,642 ÷ 1,694，约 96.9%；它衡量订单覆盖，不衡量门店库存是否够卖。 |
| 订单缺口 | 已确认订单中尚未配到车的数量。 | 1,694 − 1,642 = 52 辆。即使船上还有其他车型，也不能直接替代这 52 辆的需求。 |
| 可补库池／可注水池 | 扣除预留和已分订单后，还能用于门店补库的车辆。 | 2,500 − 250 − 1,642 = 608 辆；这只是进入下一轮补库的供给上限。 |

**本轮交给下一步的是 608 辆可补库车辆和仍未解决的 52 辆订单缺口。** 两者按不同车型与用途管理，不能相互抵消，也不能把已分给订单的 1,642 辆再用一次。

## 四 余车怎样按门店需求补库

利雅得凯美瑞卖得快，可能比另一家库存相同的门店更早缺车。因此补库先计算销速和库存覆盖，再确定目标及缺口，最后通过注水策略分配有限车源。

### 先算当前还能卖多久以及应该补多少

| 名词 | 含义 | 用示例门店的凯美瑞理解 |
| --- | --- | --- |
| 补库／补货 | 为门店后续销售补充尚未绑定具体客户的库存。 | 在已售订单得到优先保障后，再给利雅得门店补凯美瑞，以接住后续客户需求。 |
| 周销速 | 平均每周销售的车辆数量，单位为辆／周。 | 假设该店凯美瑞每周卖 10 辆，20 辆自由库存大约够卖两周。 |
| 八周周均销速 | 指定八个完整周的销量合计除以 8。 | 用历史凯美瑞销售节奏作为参考；项目中的月报折周也属于参考口径，不能说成实测周报或销量承诺。 |
| 销速系数 | 对基准销速施加的情景乘数。 | 设为 1.2，相当于按每周 12 辆预测消耗；原始历史销量仍保留。 |
| WoS／库存覆盖周数 | Weeks of Supply，库存按参考销速可支撑销售的周数。 | 销速系数为 1 时，该店自由库存 WoS = 20 ÷ 10 = 2 周；实物库存 WoS 要另按实物范围计算。 |
| 目标 WoS／目标水位 | 希望门店达到的库存覆盖周数。 | 本船补库默认基准 4 周；这是希望补到的位置，不是该店当前已有的库存。 |
| 直营目标系数／绩效目标系数 | 对基准目标 WoS 施加的情景乘数。 | 直营目标系数用于直营店，绩效系数仅用于勾选门店；它们调整目标，不修改原始销量。 |
| 目标库存 | 达到调整后目标 WoS 所需的库存数量。 | 若系数均为 1，则该店目标为 10 辆／周 × 4 周 = 40 辆。 |
| 库存满足率／水位 | 自由库存占目标库存的比例。 | 20 ÷ 40 = 50%；这家店已达到目标的一半，与客户订单已配齐多少是两回事。 |
| 补库缺口 | 为达到目标库存还需补充的数量。 | 此例还缺 40 − 20 = 20 辆凯美瑞；实际能补多少仍受本船凯美瑞余量限制。 |

### 再决定有限车源先补谁

| 名词 | 含义 | 放到当前补库决策中理解 |
| --- | --- | --- |
| 渠道级差 | 注水时设置的直营与授权渠道优先差异。 | 默认 10 个百分点，影响两类渠道的分配优先；不是给直营固定多分整船的 10%。 |
| 畅销与滞销搭配 | 按设定比例搭配同品牌的畅销与滞销车型。 | 项目默认 8:1，可关闭；用于解释为什么有凯美瑞补库需求，也不一定能只拿畅销车型。不是 ALJ 真实合同条款。 |
| 注水／注水分配 | 在车型、目标和渠道等约束下，逐辆补给水位较低且可以接收的门店。 | 同样只有 20 辆自由库存，周销速较快的店水位更低；分配还要结合渠道级差与可用车型。 |
| 门店补库量 | 本轮实际分给门店用于补库存的数量。 | 608 辆可补库池中实际分出 506 辆，其中直营 484 辆、授权 22 辆。 |
| 留仓／未分配车辆 | 未进入本轮订单或门店补库分配的剩余车辆。 | 剩余 102 辆单独留仓；它们与主动预留的 250 辆分别列示，后续使用需确认可释放范围。 |

如果示例门店最终补到 10 辆凯美瑞，其自由库存从 20 辆变为 30 辆，WoS 从 2 周变为 3 周，满足率从 50% 变为 75%，仍距 4 周目标差 10 辆。

**默认本船数量守恒：2,500 = 250 预留 + 1,642 订单分车 + 506 门店补库 + 102 留仓。** 车型结构和分配约束使“有总量余车”与“仍有车型缺口”可以同时发生。

## 五 分到门店的车怎样真正送到店

归属确定后，还要让车辆完成出库准备、匹配门店接车条件，再组成运输批次。吉达分给利雅得的车，可能直接到店，也可能先到 VPC，等待后续订单触发配送。

### 先落实车辆可发以及门店可接

| 名词 | 含义 | 放到当前吉达单港场景中理解 |
| --- | --- | --- |
| 清关 | 到港车辆完成海关相关手续的环节。 | 2,500 辆船量不表示到港当日就全部可以出库配送。 |
| PDI／交付前检查 | Pre-Delivery Inspection，车辆交付前的检查。 | 丰田或雷克萨斯车辆需按相应要求完成检查；清关、检查、加装和整备分别关注。 |
| 停车余量 | 门店总库容扣除全部品牌实物库存后的剩余空间。 | 利雅得门店的锁定车、冻结车仍占停车位；兼营雷克萨斯时也要计入其车辆。 |
| 接车能力／收货窗口 | 门店在指定时段可接收的车辆数量与时间安排。 | 有停车位也不代表今天能一次接收整批凯美瑞，可能需要分批到店。 |

### 再确定路径与暂存安排

| 名词 | 含义 | 放到当前吉达单港场景中理解 |
| --- | --- | --- |
| 单港／双港 | 分别以吉达，或吉达加达曼作为进口运输入口的比较情景。 | 主线使用单港方案，双港用于比较；不能把两个方案中的供给和运力相加。 |
| 直送 | 从当前起运点直接运到目标门店。 | 本船补库中主要指港口直送门店；每日调拨中的直送则可从 VPC 或来源门店起运。 |
| VPC 暂存 | 已分配车辆先存放在 VPC，稍后再送门店。 | 默认 506 辆补库车中，132 辆直送、374 辆暂存；暂存部分已有门店归属，但尚未形成门店实物库存。 |
| 干线／首程 | 从港口或主要车源点到城市、中心或门店的大段运输。 | 例如吉达向利雅得方向运输，需看该批车辆究竟到中心还是直接到店。 |
| 末端配送／末程 | 中心或区域车源点到最终门店的后续运输。 | 同一辆车的首程和末程是两段移动，不能因此把一辆车算成两辆新增供给。 |
| 订单触发配送 | 补库车先暂存，出现有效订单后再安排中心至门店配送。 | “满载待订单”仍需订单条件成立；“待拼车”仍未满足该模拟方案的发车条件。 |

### 最后组成车次并跟踪到达

| 名词 | 含义 | 放到当前运输安排中理解 |
| --- | --- | --- |
| 板车／轿运车 | 承运商品车辆的运输车辆。 | 一辆板车可以运多辆丰田或雷克萨斯，需区分承运车辆数和商品车数。 |
| 板车容量 | 一趟最多承运的商品车数量。 | 补库模拟可设 8–10 辆；每日调拨另设大车最多 8 辆、小车最多 2 辆，两套参数不能混用。 |
| 运力 | 特定时段与路线可完成的运输能力。 | 多家同城门店可能共享一条城市路线，不能每家店重复使用完整路线额度。 |
| 拼车／拼载 | 把多笔订单的商品车合并运输。 | 沿线几家丰田门店各要少量车时，可一起发运以分摊运费，但要满足各自交期。 |
| 班次／车次／运输批次 | 一趟运输及其车源、车辆、目的地和时间安排。 | 当前每日示例的 88 辆区域有货车组成 23 个计划批次；一个批次可合并多笔订单，实际发车仍需承运确认。 |
| 卸货点 | 同一批次沿线交车的地点。 | 当前每日大车最多 3 个卸货点，不能只要车位够就无限增加沿线门店。 |
| 装载率 | 实载车辆数占单趟容量的比例。 | 容量为 8 辆、实载 6 辆时为 75%；装载率高还需结合到店时效判断。 |
| ETA／预计到店时间 | Estimated Time of Arrival，预计到达目的地的时间。 | 看清是到港、到 VPC，还是到利雅得门店；预计到达也不等于已签收或已交付客户。 |
| 发运／在途／签收 | 分别指已经起运、运输途中、收货方确认收到车辆。 | 分车和生成计划是前置安排，车辆实际移动与到店需要这些执行记录证明。 |

## 六 后续每天有新订单时怎样找车

本船计划解决的是一批供给的分配；门店每天销售后，又会出现新需求、取消和待处理订单。每日调拨先整理有效需求，再按车型、配置、颜色及时间条件检查车源。

### 先整理今天真正需要处理的需求

| 名词 | 含义 | 当前每日演示中的例子 |
| --- | --- | --- |
| 新增订单 | 当天新进入需求池的有效订单。 | 32 笔、61 辆，是今天新增的需求。 |
| 待拼车订单／积压需求 | 上一业务日尚未安排完成、继续滚入今天的需求。 | 16 笔、33 辆，不能因为不是当天新增就漏掉。 |
| 取消订单 | 已撤销、不再进入有效调度的订单。 | 4 笔、7 辆单列展示；相关车辆能否释放还需核对占用和执行状态。 |
| 今日有效需求 | 今天需要处理的新增与待拼车需求。 | 32 + 16 = 48 笔，61 + 33 = 94 辆；此总数已经不含取消订单，不应再减一次。 |
| 需求门店／目标门店 | 需要接收车辆以履行订单的门店。 | 先明确客户由哪家丰田或雷克萨斯门店交付，再寻找合适车源与配送路径。 |
| 交期／交付承诺 | 订单要求达到的到店或交付时间条件。 | 当前 LX 急单要求 24 小时内到店；车辆按期到店后，仍需完成门店的客户交付安排。 |

### 再判断本区能否满足以及缺货怎么补

| 名词 | 含义 | 放到丰田与雷克萨斯车源匹配中理解 |
| --- | --- | --- |
| 车源／候选车辆 | 为某笔订单找到的具体供选择车辆。 | 需要匹配车型、配置和颜色，并核实可用性；两笔订单不能同时占用同一辆 LX。 |
| 区域有货 | 已在服务 VPC 或区域门店匹配到可用同配置车辆。 | 94 辆需求中，88 辆进入有货配送安排；“有货”仍不等于已经到店。 |
| 区域缺货 | 服务 VPC 和区域门店没有可用的同配置车辆。 | 剩余 6 辆需要继续比较其他区域车源或本区授权车商，不表示全国无车。 |
| 调拨 | 调整已有车辆的位置或业务归属。 | 从一处 VPC 或直营店把车送给缺车门店，不增加全国实物车辆总量。 |
| 跨区调拨 | 从其他区域取得车辆并配送到需求门店。 | 可以补上本区没有的 LX 配置，但更长的运输距离可能使它赶不上急单交期。 |
| 本区授权店采购／回购 | 从本区授权车商购买车辆以满足需求；历史材料也称回购。 | 可能更快取得指定 LX，但要确认采购价、车况、权属与结算；不是客户退车，也不等于内部调拨。 |
| 改派 | 改变已有分配的目的门店或用途。 | 原分给达曼门店补库、仍在 VPC 的凯美瑞若改给利雅得，需要记录原门店损失与补回安排。 |
| 最低安全线 | 为来源门店保留必要销售保障的最低库存或覆盖阈值。 | 调走凯美瑞后是否跌破安全线，需要核实；它与希望补到的目标水位分别判断，例外需取得对应业务决定。 |
| 源店影响 | 调出车辆对来源门店的订单、销售能力和原补库安排造成的影响。 | 最近的门店有自由凯美瑞，也可能因调出后更易断货而不适合提供车源，应同时看目标端收益与源店损失。 |

## 七 比较车源时怎样看交期成本与利润

找到同配置车辆后，要在能否按期到店、取得车源的代价和订单利润之间做取舍。当前演示将区域缺货车逐辆比较；补库页面的利润则用于评估一批车辆全部售出的经营情景。

### 先统一收入与成本口径

| 名词 | 含义 | 放到 ALJ 的销售与采购方向中理解 |
| --- | --- | --- |
| SAR | Saudi Riyal，沙特里亚尔，金额使用的币种代码。 | 采购、运费、收入和利润都要保持币种一致，并区分 SAR／辆与 SAR／趟。 |
| 零售价／批发价 | 向终端客户销售与向授权渠道供货的价格。 | 项目从供货方视角看直营零售收入和授权批发收入；后者不是授权车商最终卖给客户的收入。 |
| 价格系数 | 对基准价格施加的情景乘数。 | 车型与全局系数共同作用；1.01 表示相应基准的 101%，用于观察价格调整对预计经营结果的影响。 |
| 未税净收入 | 不含税、按相应销售口径确认的净收入。 | 每日 LX 候选方案以同一客户订单收入为起点，比较两条取得车源路径的成本。 |
| 采购成本／采购金额 | 取得车辆的成本；采购金额是单据中各车辆采购价的合计。 | 自有车源仍有原采购成本；从授权车商取得 LX 则使用候选采购报价。采购金额之外还需看物流与其他费用。 |
| 整趟费用／单车分摊运费 | 一趟总运费及分给每辆商品车的费用。 | 每日拼载批次按车辆均摊并处理尾差，各车费用相加等于该趟总费用。 |
| 单车物流预算 | 补库模拟中为每辆车估算的全程物流费用。 | 与门店基准、物流系数和容量联动；尾班按预算计费，不代表真实承运商对不足一车也这样报价。 |
| 佣金／其他归属费用 | 能归到该订单或车辆的其他费用。 | 比较两种 LX 方案时，不能只比运费，也不能把已经包含在某项成本中的费用再扣一次。 |
| 直营单车固定费用 | 补库模型按直营单车设定的费用。 | 从直营毛利中扣除；授权渠道该项设为 0，是当前模型口径，不是对真实企业全部固定费用的描述。 |

### 再计算不同页面的利润

| 名词 | 含义 | 当前页面怎样使用 |
| --- | --- | --- |
| 单车毛利 | 对应销售价格减采购成本。 | 直营按零售价算，授权按供货方批发价算；都还没有扣除相应物流等费用。 |
| 单车净利／预计总净利润 | 补库模拟在毛利上继续扣除本店物流和设定费用后的单车或汇总结果。 | 用于比较补库参数；并不是 ALJ 企业完整的税后净利润。 |
| 贡献利润 | 未税净收入扣采购、物流、佣金及其他归属费用后的余额。 | 每日缺货比较用它判断不同车源路径还能留下多少订单贡献，不默认覆盖全部固定经营费用与税费。 |
| 贡献利润率／净利润率 | 对应利润占同范围收入的比例。 | 汇总时用利润合计除以收入合计，不能直接平均各车或各店利润率。 |
| 预计营业额／预计利润 | 假定本轮补库车辆全部售出后的情景测算。 | 分给利雅得的凯美瑞尚未销售时，不能把这一测算记为已经发生的收入与利润。 |

**补库页面公式：**

- 直营单车毛利 = 零售基准价 × 车型零售系数 × 全局零售系数 − 采购价。
- 直营单车净利 = 单车毛利 − 本店单车物流预算 − 设定的直营单车固定费用。
- 授权单车毛利 = 批发基准价 × 车型批发系数 × 全局批发系数 − 采购价。
- 授权单车净利 = 单车毛利 − 本店单车物流预算。

**每日方案公式：贡献利润 = 未税净收入 − 采购成本 − 物流费用 − 佣金及其他归属费用。**

必要费用未知或运输未落实时，应保持待确认；未知费用与明确为 0 的费用含义不同。

### 用当前 LX 急单理解方案取舍

该演示订单要求 24 小时内到店，两条路径如下：

| 候选路径 | 预计到店 | 单车贡献利润 | 对这笔订单的意义 |
| --- | --- | --- | --- |
| 跨区调拨 | 35 小时 | 20,568 SAR | 留下的利润较多，但超过承诺 11 小时。 |
| 本区授权店采购 | 6 小时 | 2,617 SAR | 取得车辆的代价较高，但可以满足到店承诺。 |

此例选择本区采购，是用较低的贡献利润换取按期到店。它不表示所有雷克萨斯都应采购，也不表示所有丰田订单都应等待；仍需逐单比较合格车源、交期和费用。

## 八 选定方案后怎样形成单据并执行

比较结果之后，先确定每辆缺货车采用哪个方案，再生成配送与采购草案，最后核实条件并跟踪实际执行。车辆匹配、商业交易和运输是关联的不同记录。

| 名词 | 含义 | 当前缺货处理中的顺序与含义 |
| --- | --- | --- |
| 推荐方案 | 系统比较候选后提出的建议。 | 页面推荐考虑交期；LX 急单更适合能按期到店的本区采购。 |
| 已选方案／默认补齐 | 已选是用户明确指定的候选，默认补齐用于尚未手选的车辆。 | 生成单据时手选优先；未手选车辆按贡献利润最高选择，同利润时优先更快到店。默认结果仍可能超期。 |
| 待复核 | 方案存在需要人工核实或处理的问题。 | 当前单据对亏损或超期标记待复核；不能因为已经生成草案，就认为问题已解决。 |
| 缺货调度建议 | 按最终选定候选生成的逐车配送草案。 | 只处理 6 辆区域缺货车，不重复安排前面 88 辆区域有货车。 |
| 授权店采购订单 | 对选择授权店采购的车辆生成的商业采购草案。 | 同一供应商、同一收货门店可合并；跨区调拨车不进入采购单。 |
| 重新生成 | 改选候选后，按最新选择更新相关草案。 | 两辆 LX 改为本区采购后，应更新配送与采购单，不能继续使用旧选择对应的单据。 |
| 执行完成 | 车辆、交易和运输条件落实后，按实际发运、签收等记录确认业务结果。 | 到店签收与采购结算分别跟踪。当前演示生成的草案或导出文件，不会直接锁定真实车辆、采购或发布运输任务。 |

当前操作示例中，6 辆缺货车选为 **4 辆跨区调拨 + 2 辆授权店采购**，形成 6 条配送建议。两辆 LX 的供应商和收货门店相同，合并为 **1 张采购单**，采购金额为 **1,138,500 SAR**；物流与其他费用另列。采购车辆数、订单笔数和单据张数分别计量。

## 九 在系统中怎样提出任务和保存结果

业务上先明确要看什么、要比较什么，再通过对话发起任务；参数修改先形成预览，运行后才成为可回看的版本，最后按已生成结果导出计划。

| 名词 | 含义 | 在当前操作中的位置 |
| --- | --- | --- |
| Agent | 整理需求、运行模拟、解释结果并提出方案的助手。 | 帮助 ALJ 场景中的分车员和调拨员分析任务，业务确认与实际执行仍需相应记录。 |
| CUI | Conversational User Interface，对话式用户界面。 | 用对话提出“查看本船缺口”“调整基准 WoS”“生成今天调拨计划”等任务。 |
| Skill | 可通过斜杠命令启动的业务能力。 | 根据当前任务调用问数、订单分车、补库或每日调拨等能力。 |
| GUI／画布 | Graphical User Interface，图形用户界面。 | 查看门店水位、车辆路线、逐车候选和利润表，并通过按钮调整或确认选择。 |
| 实时预览／草稿参数 | 改了参数、尚未正式运行的试算状态。 | 调整凯美瑞价格或渠道级差后，经营指标可实时预览，分车与物流明细仍引用上次运行版本。 |
| 运行模拟 | 应用有效草稿参数并保存本次情景。 | 运行后相关分车、物流和利润统一引用新版本；参数无变化时不重复生成。 |
| 情景版本／快照 | 某次运行保存的参数、结果与数据时点。 | V1、V2 等用来比较“这次为何给直营多分了车”，不表示真实库存已经发生对应变动。 |
| 画布历史 | 同一任务已生成的业务结果记录。 | 可以回看问数、订单分车、补库、每日调拨和缺货单据。 |
| 导出计划／JSON | 导出保存当前计划；JSON 全称为 JavaScript Object Notation，JavaScript 对象表示法。 | 文件保留订单、车辆、运输批次、方案选择与采购草案，不是承运回执或真实采购凭证。 |

### 五个主线 Skill 的业务顺序

| 命令 | 页面名称或常用叫法 | 接续的业务问题 |
| --- | --- | --- |
| `/query` | 基本统计／智能问数 | 本船有哪些车，哪些车型或门店缺车？ |
| `/order-allocation` | 订单分车 | 哪些已售订单能由本船配齐，还缺哪些车型？ |
| `/vessel-allocation` | 分车计划模拟／补货模拟 | 扣除预留与订单后，608 辆如何补库，物流和经营结果怎样？ |
| `/daily-dispatch` | 每日调拨计划 | 今天的有效需求有哪些，区域车源能满足多少？ |
| `/shortage-fulfillment` | 缺货调度与采购订单 | 对区域缺货车，按选定路径生成哪些配送与采购草案？ |

本船三个环节使用 **2026 年 8 月 5 日**模拟快照；每日两个环节使用 **2026 年 10 月 7 日 08:30 沙特当地时间**的独立快照。故事中的 T 与 T+1 表示业务顺序，两份快照没有逐日扣减联动，因此 94 辆每日需求不能记为本船 608 辆补库池的当日销售或出库。
