> 本文给出页面结构、线框、指标及数据映射。CSV汇总已经核对；本地前端已提供品牌筛选、供需月度趋势、库存可用性、区域与网点库存、路线模板和数据体检。本文其余扩展视图仍为目标设计，具体演示入口见[完整故事脚本](./04_CUI与GUI完整故事脚本.md)。

## 1 工作台布局

桌面端采用左侧任务列表、中部业务工作台、右侧可收起 CUI。建议1440像素桌面以约200像素任务区、360像素对话区规划，其余空间交给工作台；宽表可暂时收起任务列表或对话。窄屏在“对话”和“工作台”间切换，保留当前任务和选中对象。

原有计算图谱、参数和发布能力通过工作台页签或详情入口访问。日常操作的主路径为“数据分析 → 策略调整 → 分车结果”，不要求用户先理解计算节点。

```text
┌任务列表────────┬周度分车 W1 · 丰田 · 演示推演──────────────────┬CUI───────┐
│ 本次分车任务   │ 数据分析  策略调整  分车结果  方案对比         │ 用户诉求 │
│ 其他任务       │ 范围：全国 / 丰田 / 全渠道   数据版本 / 情景  │ 执行进度 │
│                │ 数据时效与缺口提示                            │ 分析摘要 │
│                │ 供给规模   历史需求强度   自由库存   道路容量 │ 建议卡片 │
│                │ 供需趋势与结构       库存覆盖与低库存网点     │ 追问输入 │
│                │ 路线能力与费用       关键发现及下一操作       │          │
│                │ 区域 / 渠道 / 门店明细                        │          │
└────────────────┴──────────────────────────────────────────────┴──────────┘
```

点击 CUI 的“查看利雅得线路”会在工作台打开路线抽屉并定位相关行；点击图表的“分析此范围”会将明确的对象和版本附入 CUI 输入，用户可以直接继续提问。

## 2 先让用户知道数据是否足够

顶部显示一个常驻数据状态条，默认折叠为一句结论，点击展开检查清单。

现有数据对应的结论应是：**可进行品牌和路线压力分析；正式逐车型分车仍缺输入。**

| 检查类别 | 当前情况 | 页面行为 |
| --- | --- | --- |
| 网点与关联 | 79店、46经营主体、99个店×品牌组合 | 正常展示；主体、门店、品牌组合分别计数 |
| 月度销量/供给代理 | 有效值为2025-01至2026-07，8/9月为空 | 趋势断开，空值标“缺数据”，不画成零 |
| 销速时效 | 直营截止7月26日、授权店截止7月31日 | 展示时间窗；距9月29日快照分别65/60天 |
| 库存 | 9月29日独立模拟快照 | 明示性质，不能声称由历史流水滚动重建 |
| 车型明细 | 缺逐店车型销量、各状态库存等 | 品牌分析可用；车型层仅展示显式演示情景或已补齐部分 |
| 订单/在途/供给释放 | 缺订单核销、在途到达日、真实释放批次 | 订单及时满足率等显示“未计算” |
| 道路资源 | 双港口/仅吉达两套互斥模拟场景 | 选一个作为当前情景，可并排比较 |
| 入口承接能力 | 未提供船期、卸车、VPC处理能力 | 道路容量不能被解释为整个进口链路容量 |

检查项显示检查结果、影响范围、输入来源和可执行动作。不计算一个难以解释的“数据健康分”。检查失败、数据缺失、过期和情景假设分别表达。

## 4 供给与需求面板

### 4.1 历史趋势

主图用月份为横轴、台数为纵轴，按品牌切换2025-01至2026-09。供给代理的有效数据截止7月，8/9月标为缺失。直营和授权店月销量用堆叠柱表现，供给代理用参考线表现。

**来源关系必须显式提示**：这批模拟月销量本身按G/H生成，合计与供给代理一致。重合不是实际经营供需平衡的证据。该图主要检查规模变化和渠道分布，不用于推断“真实供给正好满足需求”。

周销速另作小图，显示直营8周窗口与授权店92天月报折周口径；授权店周明细标注“月报拆周”，不显示为实测周报。

### 4.2 车型供需结构

有车型级输入后，用横向并列条形图比较“本期供给规模”和“参考消耗”，旁边列出期初自由库存、及时在途、期末目标、净补库需求，避免只看两根柱子就判断最终缺车。

现阶段可加载已有 W1 的15车型演示结构，图标题必须写“车型流量对照，演示假设”。例如凯美瑞394台对546台、兰德酷路泽300为125台对87台，分别是新增流量偏紧和流量相对充裕，不能据此判定前者必缺或后者滞销。

没有补齐逐车型库存的列统一显示“缺车型明细”。用户选择具体车型时不得继续显示品牌库存数字并只换标题。

### 4.3 供给去向瀑布图

正式供给或演示批次补齐后，展示 S供给基数 → X不可用/未释放 → P既有承诺 → R预留 → Q净可分 → 直营/授权预算。每个扣减类别互斥，来源为B4。当前只能得到供给规模时，后续步骤留空，不默认所有2,010台都可分。

### 5.1 品牌库存分解

库存状态用堆叠条形图，自由、已锁、冻结三段合成实物；在途独立显示在旁边，避免视觉上并入实物。

| 品牌 | 实物 | 自由 | 已锁 | 冻结 | 在途另列 | 91天及以上库龄 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 丰田 | 6,011 | 4,688 | 1,091 | 232 | 924 | 303 |
| 雷克萨斯 | 698 | 544 | 132 | 22 | 88 | 35 |
| 合计 | 6,709 | 5,232 | 1,223 | 254 | 1,012 | 338 |

源表2,107台采用原3/4周目标、直接减全部在途且未计规划期消耗，名称保持“源表参考补库缺口”。运行中 B7 净需求考虑当前参数、及时在途和期间消耗，应另列，不能要求等于2,107。

### 5.3 库存风险分布

采用“周销速 × 自由覆盖”的散点图，一点一个门店×品牌；补齐后可切换为门店×车型。点面积表示实物库存，颜色表示渠道；选中点显示库龄、订单、在途以及数据时间。

可编辑分析阈值初始设为自由覆盖＜1周与＞6周，只用于筛选，不改变分车规则。当前前者有7个组合，后者为0；不能因为没有＞6周就宣称没有积压，库龄与车型结构还需独立检查。零销速点列在单独清单，缺销量也单列，均不通过加一个极小分母放入图中。

详情抽屉显示该门店各品牌/车型的状态、目标来源和数据证据；“针对该店调整策略”打开草稿并预选范围，不直接改最终分车数。

## 7 关键发现与策略入口

看板右下区域按决策影响列出三至五条发现，每条固定包含“观察 → 影响 → 建议 → 依据”。例如：

> 仅吉达情景下，利雅得路线历史需求压力缺口为150台。相关门店本期新增发运量可能受限，应按真实订单时限、门店可用库存和本期分车重新检查。可打开该线路门店清单，或进入单港口策略试算。

动作包括查看明细、在CUI解释、创建策略草稿、比较场景。分析结论只引用当前可见的证据；在途日期缺失时不写“能撑到某一天”，车型库存缺失时不写“某车型已积压”。

## 8 策略与结果页面如何接续

策略页上部显示情景假设和业务目标，中部按车型策略组排列建议卡，下部是参数差异表及“试算”。变化用原值→新值表示；供给假设、运输资源和业务分配参数分组，防止用户误以为它们是同一类开关。

结果页采用以下顺序：

1. 本运行覆盖范围、版本、共享校验状态。
2. 新分车量、未分配、固定口径要货满足率、订单及时满足率、国内道路总费和台均费。
3. 与同一冲击情景下“策略未调整”的对比，显示哪些地区/渠道/门店增减。
4. 经营主体 → 门店 → 车型表，展开来源及路线，点击数量打开“为什么这样分”。
5. 剩余缺口及原因、可能改善的参数、下一步动作。

费用、满足率和解释公式统一见[结果口径](./03_港口受限策略与结果解释.md)。没有正式要货单时改称“模型补库需求满足率”，不能借一个相近指标显示为经销商真实要货满足率。
