| O1_需求侧宽表       | O1 销售网点、销量、库存原始输入                         | 保留原始口径；增加网点及车型维度契约；手工业务系数归黄色配置    |

| B3_库存合并宽表     | B3 有效库存及逐日投影                               | 实物、自由、在途、负净资源分开，覆盖单位统一为周                |

| A6_保底配置、B5_保底 | 本版删除，不复用编号 | 不生成节点、字段、阶段或GUI表单；历史参考文件保持原样 |
| B6（原参与排除相关对象） | B6 资格与排除原因 | 仅保留资格及候选用途，无最低铺货路径 |
| B7_参与分货商宽表 | B7 订单需求与可分上限 | 订单与净补库不重复相加；按网点所属渠道参与 |
| B8_注水算法结果 | B8 渠道内分配轮次 | 订单、普通注水、扣减和回流；阶段与累计量分开 |
| B9_留仓量           | B9 未分配及预留                                     | 政策预留、自由未分配、未释放分别表达，不统称实物库存            |
| B10_最终分货结果    | B10 最终分车明细                                    | **补交易身份、门店、来源批次和用途**，支持按车型汇总      |
| 本次新增            | B0 数据适配，B11 共享约束；O5 物流资源，O6 订单占用 | 补足现有CSV→车型计算→可发布计划之间的缺口                     |

参考表 B10 未列交易身份/门店主键，且“轮次”出现两次，本方案修正为唯一的`run_id + allocation_line_id`，用门店、车型、来源、需求用途等字段约束业务唯一性。多轮由B8事件表达，B10只保存本次有效结果，不重复保留同一车辆的多轮总量。

原材料有“库存÷日均销速”仍标为WOS的表述，本方案统一为`库存÷周销速`；“台/日”的字段不会直接除出“周”。这些是设计口径调整，未修改参考文件。

业务层与GUI统一称“销售网点”，渠道显示“直营店/授权店”，主体显示“经营主体”。原`客户类型`映射为`channel_type`，原`客户名称`在主体表映射为`operating_entity_name`，`门店名称`映射为`store_name`；不把主体名称覆盖为物理网点名称。`store_id`继续承接原门店编码，`trade_identity_id`承接原交易身份编码，无须为改名重建ID。原文件路径和列名仅在来源映射中展示。

核心业务键为`planning_week + store_id + model_id`，`run_id`用于版本隔离。车型粒度和沙特称谓依据见[主方案第3节](./01_周度分车模块设计方案.md#3-计算粒度与对象边界)。颜色、配置、年款和VIN不是本模块主键、筛选字段或必填输入；上游明细按车型归并并保留追溯引用。

## 3. 公共键与数据类型

### 3.1 任务和运行

| 对象       | 字段                                                                                           | 含义                                            |
| ---------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| S1周计划   | plan_id、planning_window、business_timezone、owner                                             | 一个经营周的跨车型计划                          |
| S1车型任务 | task_id、plan_id、model_id、channel_scope | 一个车型任务内同时管理直营与授权两个渠道池 |
| S2参数版本 | parameter_version_id、name、status、effective_period、rule_set                                 | 不可变版本；草稿编辑后形成新版本                |
| 运行       | run_id、plan_run_id、task_id、parent_run_id、scenario_id                                       | plan_run_id固定参与联合校验的所有车型运行ID清单 |
| 冻结依据   | data_snapshot_id、parameter_version_id、graph_version、algorithm_version、resource_snapshot_id | 决定一次结果，可回放、可缓存                    |

正式发布引用同一`plan_run_id`的B12联动及B11联合校验结果。不能把车型A新运行与车型B旧运行随意拼成总量，再复用之前通过的搭配或资源检查。B12为跨车型运行级产物，引用组内所有task_id/run_id；任一成员变化即失效。

## 4. 灰色节点详细定义

### B0 标准化与车型展开

- **粒度**：来源记录×门店/车型/状态/期间，供给另按来源批次。
- **依赖**：O1、O3及主数据/演示输入假设快照。
- **输出字段**：`store_id, trade_identity_id, channel_id, channel_type, model_id, source_grain, source_quantity, split_ratio, split_quantity, rounding_delta, eligibility_source, data_nature`。
- **计算**：标准化键和单位；演示按冻结的数据准备假设独立展开；整数守恒。正式车型明细不再二次拆分，源颜色/配置明细先按车型归并；A1不参与此步。
- **异常**：重复主键、未知车型、比例不等于1、无状态拆分、缺品牌资格。
- **GUI**：原记录与展开明细并排，展示“79店/99个店品牌组合”和实际展开数量；不固定宣称有79×15条有效组合。

### B1 需求与销售速度

- **粒度**：门店×车型×需求时间桶；汇总行至规划周。
- **依赖**：B0、O2、O6、A3。
- **输出字段**：`history_qty, history_days, sales_velocity_week, sales_velocity_day, velocity_source, velocity_as_of, demand_correction_factor, forecast_qty, forecast_consumed_qty, residual_forecast_qty, unbound_order_qty, consumption_qty`。
- **计算**：历史窗折算；按有效规则选择预测口径；先核销预测再形成消耗。零销量和缺失分开。
- **异常**：时间窗不完整、数据过期、订单核销信息不足。
- **GUI**：基础销量、窗口和转换公式，明确L2“月报折周”；政策绩效不修改原始销量。

### B2 目标覆盖

- **粒度**：门店×车型×规划窗口。
- **依赖**：B1、A5；主体/渠道/区域标签通过B1继承B0引用。
- **输出字段**：`target_template_id, target_inventory_basis, reference_wos_low, reference_wos_high, base_wos, performance_factor, channel_factor, region_factor, combined_factor_raw, combined_factor_used, target_wos, target_qty_raw, target_qty, target_rounding_delta, outside_reference_band`。
- **计算**：新4S模板基准5周、参考4–6周，明确一期自由库存口径；各系数类别唯一命中、相乘后截断；目标数量向上取整。旧CSV的3/4周保持原样；新版教学算例显式使用5周模板。
- **异常**：重叠规则冲突、系数越界、非零目标但基础销速缺失。
- **GUI**：公式代入和政策来源；可跳转对应黄色参数节点。

### B3 有效库存与逐日投影

- **粒度**：门店×车型×日期；另有规划期末汇总。
- **依赖**：B0、B1、O6、A4。
- **输出字段**：`physical_qty, free_qty, locked_qty, frozen_qty, inbound_total_qty, timely_free_inbound_qty, uncertain_inbound_qty, consumption_qty, net_resource_e, projected_free_qty, shortage_without_new_supply, uncovered_order_protection_h, wos_before, physical_wos_before, projected_wos_without_allocation, daily_physical_projection`。实物覆盖含锁定/冻结、在途另列，与自由库存覆盖分开。
- **计算**：三状态守恒，区分及时自由在途，逐日匹配，负E单独表达不足。
- **异常**：锁定重复、在途已到但未核销、到达时间未知、库存过期。
- **GUI**：库存组成、逐日到货/消耗、缺口发生日，覆盖值附基准时间。

### B4 车型供给及渠道池

- **粒度**：总账为供给批次×车型×来源×可用时段；渠道预算为运行×车型×渠道。两张表关联，不把全国Q重复计入渠道合计。
- **依赖**：B0、O6、A1、A2。
- **总账字段**：`supply_batch_id, model_id, source_location_id, supply_basis_qty_s, unavailable_qty_x, existing_commitment_qty_p, policy_reserve_qty_r, allocatable_qty_q, release_at, supply_nature, deduction_refs`。
- **渠道预算字段**：`channel_pool_id, model_id, channel_type, split_rule_id, split_ratio, unrounded_budget, rounding_delta, channel_budget_qty, source_ledger_refs`。
- **计算**：先S=X+P+R+Q，再按A1比例与最大余数法拆Q；直营预算+授权预算=Q。B4预算冻结，实际用量与留存由下游账本计算，不反向改写B4。
- **异常**：占用重复、净量二次扣减、渠道比例缺失或不合计1、缺必要可用时点。
- **GUI**：全国供给瀑布→直营/授权两个池→渠道内网点结果。显示比例、连续预算、取整与预算余额。

### B6 资格与排除原因

- **粒度**：门店×车型；来源/路线相关限制保留候选来源子记录。
- **依赖**：B0、B2、B3、O4、A7。
- **输出字段**：`allocation_eligible, ordinary_fill_eligible, order_candidate_eligible, policy_candidate_eligible, source_eligibility, exclusion_reasons, primary_reason, policy_conflicts, missing_required_fields`。
- **计算**：资格和限制取交集；普通高库存补库排除不删除订单特殊需求或政策候选。policy_candidate_eligible仅表示具备硬资格，A9是否允许超需求另由B12判断。
- **异常**：缺资格快照、没有合法来源、订单与限制冲突在B7合并后确认。
- **GUI**：所有候选及每条命中原因，点排除原因可见来源和规则。

### B7 订单需求与可分上限

- **粒度**：网点×车型×用途/最晚到达桶，携带唯一所属渠道池；汇总至网点×车型。
- **依赖**：B1、B2、B3、B4、B6、A8。
- **输出字段**：`channel_pool_id, channel_type, target_qty_t, net_resource_e, ordinary_need_d, demand_rounding_delta, protection_h, demand_upper, upper_u, hard_limit_components, needs_by_due_time, source_candidates, deduction_ratio, ordinary_fill_eligible, policy_candidate_eligible`。
- **计算**：D为向上取整的净需求，H为核销后的有效订单量，需求上限为max(D,H)，不做D+H；U再受硬限制封顶。政策候选可保留普通需求0的行，B12不能绕过硬限制。
- **异常**：H>U、某车型某渠道订单量超该渠道预算、无及时来源或必要字段缺失。
- **GUI**：本店需求、订单、可分上限及所属渠道预算；不呈现最低配额字段。

### B8 分车及再分配结果

- **粒度**：运行×渠道池×网点×车型×阶段/轮次，来源用途明细另表。
- **依赖**：B4、B7、A8。
- **输出字段**：`channel_pool_id, stage, round_no, cumulative_before, order_assigned_qty, lambda, continuous_delta, rounded_delta, rounding_rank, deduction_qty, refill_qty, cumulative_after, channel_used_qty, channel_remaining_qty, binding_limits, stop_reason`。
- **阶段**：`order_assignment → ordinary_fill → deduction → refill`。订单为0就从0注水，无额外的先发固定量阶段。
- **不变量**：逐车型逐渠道守恒，整数后不过上限；扣减不碰有效订单量，仅扣一次；回流不跨渠道；被实际扣减的网点×车型不参与回流。
- **GUI**：渠道预算、订单分配、普通注水及扣减回流的累计/增减两列；逐台取整能回溯到余数和并列规则。

### B12 车型搭配联动结果

- **粒度**：plan_run_id×政策组×门店×窗口×联动轮次；车辆/车型分配明细另表。
- **依赖**：B3、B4、B7、B8、A9。
- **输出字段**：`bundle_policy_id, channel_type, primary_channel_pool_id, companion_channel_pool_id, primary_model_id, companion_model_id, rule_mode, ratio, protected_primary_exempt_qty, primary_proposed_qty, companion_required_qty, ordinary_credit_qty, credit_allocation_refs, policy_extra_requested_qty, policy_extra_qty, over_normal_need_qty, primary_reduction_qty, primary_reallocated_qty, companion_release_qty, final_primary_qty, final_companion_qty, unmet_policy_qty, free_wos_after, physical_wos_after, health_limit, health_status, coupling_round, reason_codes`。
- **计算**：从主配普通量计算`ceil(r×h)`；扣除本轮普通搭配抵扣，计算政策额外量；超承接能力时硬模式回退主配，软模式保存未满足政策量。最终逐车型保留供给来源和用途，未启用政策则原样透传B8。
- **保护**：不改变已承诺/有效订单分配；本轮被秩序扣减的门店×车型不收正向增量；保持独立供给池和渠道预算。后续主配减少时撤销不必要的政策新增量。
- **健康**：自由与实物覆盖分列，按A9指定实物健康上限及绝对台数校验；零销速时必须有绝对限制。未知数据不推断为无限承接。
- **异常**：重复抵扣、重叠/循环政策、搭配不足、超健康/资金限制、无资格、缺政策依据；硬条件不能用软建议状态遮盖。
- **GUI**：主配候选→搭配要求→普通抵扣→政策新增→主配回退→最终两车型量及各自渠道预算消耗；显示政策额外量和库存风险，而不把它伪装成消费者需求。

### B11 共享约束与时序校验

- **粒度**：plan_run_id×资源×时段×校验规则；引用受影响分配行。
- **依赖**：全体车型B12、B0、O5、O6、A7及公共资源版本。
- **输出字段**：`resource_id, check_type, capacity, existing_occupancy, proposed_occupancy, remaining_capacity, violation_qty, affected_allocation_ids, check_status, missing_evidence, repair_suggestion, repair_round`。
- **检查**：各车型各渠道预算、最终搭配关系、来源释放、资源占用、跨品牌库容、跨车型路线、额度和接收/交期；搭配关系及健康限制通过B12保留的A9规则引用核验。
- **边界**：只验证车型数量层面的规划约束；具体配置匹配、VIN和装车验证在物流执行模块，不作为本模块缺数字段。
- **状态**：passed、failed、unverified；“没有发现错误”和“缺少输入无法检查”不同。
- **GUI**：点击冲突定位涉及车型、门店与分配量；修订形成新运行，不原地修改已存B8/B12。搭配车被回退时整组重算。

### B10 最终分车明细

- **粒度**：run_id×allocation_line_id，业务键覆盖门店、车型、来源批次、到达窗口、用途及需求引用。
- **依赖**：B12、B6、B11；完整候选骨架继承B6。
- **输出字段**：`planning_week, store_id, trade_identity_id, channel_type, channel_pool_id, model_id, supply_batch_id, source_location_id, demand_refs, allocation_purpose, final_allocation_qty, expected_arrival_window, order_component, ordinary_component, policy_bundle_component, bundle_policy_id, final_status, reason_codes, explanation_ref`。
- **分解**：互斥用途数量和=最终数量。有效订单与补库需求重叠的车辆按订单用途记量，不重复累加；普通量抵扣搭配仍记普通用途，只有新增policy_bundle_component记政策用途，不能重复计入两个用途。
- **结果语义**：必要的车型级规划校验未通过时保存候选状态；资格排除行可保存0及原因；缺数行用空值；正式结果包含通过的联合校验引用。
- **汇总**：业务结果以经营周×销售网点×车型为唯一行，最终分车量由来源/用途明细求和；满足率分母单独定义，不能把多用途重叠需求相加。

### B9 未分配及预留

- **粒度**：运行×车型×渠道×来源批次×互斥去向/主原因；未进入渠道的预留独立记全国池。
- **依赖**：B4、B10。
- **输出字段**：`channel_pool_id, channel_type, channel_budget_qty, channel_final_qty, policy_reserve_qty, free_unallocated_qty, unavailable_qty, existing_commitment_qty, primary_reason, secondary_reason_tags, physical_or_planned, releasable_condition`。
- **计算**：分别计算Q_channel−该渠道最终新分配，汇总等于Q−全国最终新分配；与预留、既有承诺、不可用量共同对回S。
- **异常**：任一分项负数、重复批次、B10不完整。失败运行只展示已知分项，不能补出看似完整的留存量。
- **GUI**：政策预留与自由未分配两张明细；只有具备实物依据才标“留仓”。

## 5. 黄色规则记录契约

A1记录`split_rule_id, model_scope, planning_window, direct_ratio, authorized_ratio, ratio_source, rounding_method, tie_break_channel_order, unused_policy`。比例非负且合计1，保存前展开每车型唯一生效值；`unused_policy=retain_in_channel`。跨渠道调配通过新A1版本和新运行表达，不开放隐式借量。品牌模板与车型覆盖冲突按主方案作用域优先级处理。

A5增加`target_template_id, target_inventory_basis, reference_wos_low, reference_wos_high, base_wos`，区间不是硬上限。A9作为车型搭配参数，增加`primary_model_id, companion_model_id, ratio, rule_mode, settlement_window, allow_over_demand, extra_unit_cap, physical_wos_warning, physical_wos_hard_cap, absolute_stock_cap, policy_source_id`。上限必须有明确值或明确适用状态，不能用缺失暗示无限。

A9一期只支持同店同周一对一比例、主配普通量触发、逐店累计向上取整、当期普通量唯一抵扣。多组嵌套、跨周累积、整组交付与资金返利收益优化留待有明确条款再扩展。调研依据见[4S店拿货与配额](../../02_故事设计/01_gemini调研/05_4s店.md)，不自动将参考比例视为任何具体门店的有效政策。

每条规则至少保存以下内容，GUI表单和引擎使用同一份定义：

| 字段                         | 示例                       | 说明                                   |
| ---------------------------- | -------------------------- | -------------------------------------- |
| rule_id / parameter_node_id  | `TARGET-REGION-001` / A5 | 稳定标识                               |
| scope                        | 区域=东部，车型=凯美瑞     | 支持多个条件，保存前检查覆盖冲突       |
| effect_field / effect_type   | region_factor / multiplier | 指明作用于目标，不能隐含作用于所有计算 |
| value / unit                 | 1.20 / 倍                  | 比例与百分数有明确转换                 |
| valid_from / valid_to        | 本次W1窗口                 | 到期规则不继承为永久规则               |
| priority / override_relation | 100 / 指定覆盖关系         | 解决同级冲突，仍冲突则拒绝保存         |
| policy_reason_id             | 战略区域铺货               | 识别同一原因被重复加成                 |
| business_basis / source_ref  | 用户配置的演示政策         | 不伪造绩效事实或合同来源               |
| hard_or_soft                 | soft                       | 硬约束不可自动牺牲                     |
| status / author / changed_at | 草稿 / 修改人 / 时间       | 版本留痕                               |

业务数值校验、必填条件、单位、权限和互斥关系也放在参数元数据中，前端只负责展示，后端重复校验。不能由前端删掉红色提示就绕过硬约束。

## 6. 图谱与查询接口设计

以下是逻辑接口需求，实施时适配项目已有技术结构，不假设存在某套后端：

| 能力           | 请求范围                              | 返回内容                                       |
| -------------- | ------------------------------------- | ---------------------------------------------- |
| 获取图谱定义   | graph_version                         | 节点、三色类别、边、节点粒度、公式说明         |
| 获取运行总览   | run_id / plan_run_id                  | 绑定版本、节点状态、数据完整性、指标和发布资格 |
| 查询节点明细   | run_id、node_id、筛选、分页           | 字段定义、数值、单位、状态、明细总数           |
| 解释结果单元格 | allocation_line_id、field             | 来源行、参数命中、公式代入、轮次及限制         |
| 查询上下游影响 | 节点/规则/行引用                      | 受影响门店、车型、资源及是否需要联合重算       |
| 比较运行       | baseline_run_id、candidate_run_id     | 来源/参数/算法差异、结果差量、解释状态         |
| 试算并保存     | 参数草稿＋明确输入快照                | 新运行ID及异步进度，不覆盖旧结果               |
| 发布计划       | plan_run_id、resource_version、幂等键 | 发布记录、占用结果、运输需求或具体冲突         |

图谱画布、参数表、结果表共享筛选状态和同一个run_id。图上的节点数值直接读取保存的计算产物，禁止前端另做一套销量、WOS或分配计算。

## 7. 溯源保存与校验要点

1. 一个最终结果可以追到多个来源批次和需求；保存多对多分配关系，不能只留一段解释文字。
2. 聚合数值保存组成行引用；钻到门店后仍能继续钻到输入记录。
3. 禁售、缺失、超上限和未命中规则的行也有记录，能够回答“为什么没有分到”。
4. 图谱版本、公式版本和算法版本共同冻结。新版公式不重写历史灰色节点。
5. 参数版本比较需声明数据与算法是否相同；不同数据的两个结果不能把所有差异都归因于调参。
6. 共享资源校验和发布引用同一跨车型运行集合，禁止复用不匹配的校验结果。
7. 每个节点声明字段类型、单位、粒度、入边和不变量。建图时拒绝不存在的字段、环和多对多无分摊依据的连接。
8. 本轮新增、既有承诺、实绩和情景计划分开保存。分车转为在途后使用同一占用ID迁移状态，不能两处同时累计。
