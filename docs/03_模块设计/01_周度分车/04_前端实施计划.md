# 周度分车前端实施计划

> 执行方式：本会话内连续实现；沿用已有前端样式与三栏外壳。

**目标**：在现有周度分货入口实现 v1.2 的参数、计算图谱、逐网点车型结果、版本比较及模拟发布。

**设计依据**：[模块方案](./01_周度分车模块设计方案.md)、[GUI设计](./03_GUI页面与交互设计.md)。

**结构**：Next.js 16 / React 19，复用 Card、Badge、Metric、Drawer、现有 CSS 变量。计算和输入转换放在 `frontend/src/lib/allocation/`，展示放在 `frontend/src/components/allocation/`，Planning 负责入口组合，状态进入现有 Session 快照。

## 约束

- 经营周×销售网点×车型；无配置、颜色和保底维度。
- A1先拆直营/授权渠道，池内分配及回流；供给、取整、扣减守恒。
- 4–6周参考与5周目标、绩效/区域加成、车型搭配可查看和试算。
- 蓝/黄/灰节点和结果表读取同一运行快照；调参后显示未重算，不覆盖历史结果。
- 全国源数据未补车型明细时保持缺数；全国模拟展开必须明确启用并标注假设。
- 原27台物流演示保留为独立执行样本，不将新模拟配额当作真实发运。
- 不新增框架依赖、不更换整体风格。当前目录不是Git仓库，直接修改用户指定工作区。

## 重点验证

1. 渠道比例无效、输入缺失或非整数供给：明确阻止计算，不输出伪0。
2. 参数/月份/场景变化：旧结果保持所属版本，不能发布为当前结果。
3. 搭配超承接上限：硬模式减主配，政策数量不重复算普通需求。
4. 全国模拟缺规划资源：不能伪装完整物流通过。
5. Session切换、刷新、重复发布：草稿不串会话，已保存版本不重复生成。

## 实现决策与边界

- 延续现有“周度分货”导航，工作台标题与业务内容统一采用“分车”，增加七个业务页签及独立执行样本页签。沿用现有Card、Drawer、图标库、字体与颜色变量，没有新增依赖。
- 四网点与5搭3使用独立教学供给；全国模拟显式展开949条网点×车型记录，不把品牌参考缺口冒充车型实绩。全国缺逐日资源数据，保持候选状态，禁用模拟发布。
- 当前参数为逐车型草稿，支持恢复默认和复制历史运行；先支持一组车型搭配。规则继承、批量政策管理和真实接口待后续实施，不放置无计算支持的开关。
- 主配因硬搭配回退时，数量留在本车型原渠道。本版不自动再次分配，规则页明确说明；软建议欠量在结果、B12与发布摘要显式保留。
- 全国运行快照约123万字符/版，原localStorage在连续6次试算后的刷新测试中只保留到R3。改用IndexedDB保存完整Session及冻结运行，不删历史；读取旧快照迁移，提供保存成功/失败状态。再次测试6个运行全部恢复。
- 通过原有及时刷新测试发现异步保存不能延后到固定定时器，已改为提交状态后立即保存。冻结结果和原27台执行样本分别管理。
- 独立代码审查发现的软搭配欠量展示问题已修复；搭配承接上限同时约束普通量与政策额外量，均有失败后通过的回归证据。

## 运行与查看

在frontend执行`npm run dev`，打开本地3000端口，左侧进入“周度分货”。建议先加载四网点算例，再试算、点击B网点分车量查看图谱，修改比例后生成第二个版本并比较。

生产静态文件位于frontend/out。开发、数据口径及演示流程说明见[前端README](../../../frontend/README.md)。
