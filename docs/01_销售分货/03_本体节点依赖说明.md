## 1. B1 需求合并宽表（demand_merged_wide）

主键：`task_id` × `version_id` × `trade_identity_code` × `ean` × `month` × `week_col`（6 列，前 2 列为任务/版本公共键）

**字段说明（27 列）**

**主键（6 列）**

1. `task_id` | 任务ID | 本次分货任务号，本对象所有行都挂在该任务下
2. `version_id` | 参数版本ID | 本次分货使用的参数版本，用于区分多版本产出
3. `trade_identity_code` | 交易身份编码 | 交易身份唯一编码
4. `ean` | EAN | 商品 EAN
5. `month` | 月份 | 月份，如 202609
6. `week_col` | 销售周 | 销售周列，如 2026-W38

**真实SO（5 列）**

7. `so_actual_max_date` | 真实SO截至日期 | 本次真实SO数据的最后一天，是回看窗口的右端点
8. `so_actual_total` | 本月真实SO总数 | 本月累计真实SO件数
9. `so_actual_days_in_month` | 本月真实SO天数 | 本月真实SO覆盖天数，是算日均的分母
10. `so_actual_avg_28` | 日均真实SO_28 | 最近 28 天真实SO日均，是「真实SO优先」口径的基数
11. `so_actual_avg_14` | 日均真实SO_14 | 最近 14 天真实SO日均，用于短窗口对照

**激活（5 列）**

12. `activation_max_date` | 激活截至日期 | 本次激活数据的最后一天
13. `activation_total` | 本月激活总数 | 本月累计激活台数
14. `activation_days_in_month` | 本月激活天数 | 本月激活覆盖天数
15. `activation_avg_28` | 日均激活_28 | 最近 28 天激活日均，是国内分货销速的默认基数
16. `activation_avg_14` | 日均激活_14 | 最近 14 天激活日均

**预测SO（1 列）**

17. `so_estimate_avg` | 预测SO-日均 | 周粒度 SO 预估拆成日均（来自 SO预测），是 SO 口径下的销速基数

**销售速度（4 列）**

18. `sales_velocity_alloc` | 销售速度-分货 | 分货求解使用的周销售速度（周消耗口径），由真实SO/激活/预测SO按「国内分货销售速度选择」配置加工
19. `sales_velocity_converted` | 销售速度-折算 | 卖出折算（折算成销）使用的销售速度，按「海外折算销售速度选择」配置加工
20. `sales_velocity_alloc_coefficient` | 销售速度-分货业务小区系数 | 业务小区分货销速系数
21. `sales_velocity_converted_coefficient` | 销售速度-折算业务小区系数 | 业务小区折算销速系数

**修补与替换（2 列）**

22. `replaced_velocity_alloc` | 替换后销速-分货 | 修补后的分货口径销速（仅修补行有值）
23. `replaced_velocity_converted` | 替换后销速-折算 | 替换/修补后的折算口径销速（仅修补行有值）

**口径标记（2 列）**

24. `velocity_source_alloc` | 销售速度口径-分货 | 分货销速最终命中的取数口径，如「激活 → 修补替换 → 真实SO」这条替换链的结果
25. `velocity_source_converted` | 销售速度口径-折算 | 折算销速取数口径标记（真实SO / 激活 / 预测SO / 修补）

**开关透传（1 列）**

26. `channel_patch_enabled` | 特殊渠道修补开关 | 从销售速度配置透传，供下游库存折算判断是否走纯折算

**分货周天数（1 列）** | 【新增字段，需同步补入 01 的 B1_需求合并宽表 】

27. `week_days` | 当周分货天数 | 本周实际参与分货的自然天数（1-7）；周模式恒为 7；月模式下跨月的那一周只算落在本月内的天数（如 2 天）。销速按它折算，避免最后一周需求被高估

### 1.4 计算步骤

> 输入 = §1.1 的依赖字段 + §1.2 / §1.3 的配置参数；输出 = 本对象 27 列。

#### 1.4.1 计算逻辑（业务口径）

1. **合并表**：需求侧宽表 + 预测SO，按「交易身份 × EAN」合并，落到「交易身份 × EAN × 月份 × 销售周」，再挂上销售速度配置。
2. **透传基础量**：真实SO、激活、预测SO 三组数据直接搬入（预测SO 由周拆成日均）。
3. **按口径取销速**：国内按「国内需求口径」、海外按「海外需求口径」，各自取「激活」或「SO 预测窗口」算日均需求量，再乘当周分货天数得到这一周的消耗量。
4. **销速替换**：真实SO优先 → 特殊渠道修补 → 海外SO新规，三层依次覆盖。
5. **业务小区折算**：国内行按业务小区乘销速系数（分货、折算各一套）。
6. **合成与标记**：基数 × 系数得到分货销速与折算销速，并标记这一行最终用的是哪个口径。
7. **删除无需求行**：海外零激活、且 SO 窗口也没有量的行，本轮不分货也不发保底，整行删除。

#### 1.4.2 详细步骤

1. **合并表与配置**
   - 1.1 需求侧宽表（交易身份编码 × EAN × 月份）与预测SO（交易身份编码 × EAN × 自然周）按 交易身份编码 × EAN 合并
   - 1.2 展开到「交易身份编码 × EAN × 月份 × 销售周」，得到表 1
   - 1.3 把销售速度配置的 7 个参数合并进表 1
   - 1.4 增加两个计算用字段：是否国内（按 地理大区 / 业务大区 判定）、是否修补（透传需求侧宽表）
   - 1.5 `week_days` ← 分货周天数：周模式恒为 7；月模式取该周落在本月内的天数（跨月周 < 7，如 2 天）
2. **基础量与透传**
   - 2.1 透传真实SO 5 列：`so_actual_max_date` 、 `so_actual_total` 、 `so_actual_days_in_month` 、 `so_actual_avg_28` 、 `so_actual_avg_14`
   - 2.2 透传激活 5 列：`activation_max_date` 、 `activation_total` 、 `activation_days_in_month` 、 `activation_avg_28` 、 `activation_avg_14`
   - 2.3 透传开关：`channel_patch_enabled` ← 销售速度配置
   - 2.4 预测SO 拆日均：`so_estimate_avg` = 周粒度 SO预估 ÷ 7（按 `week_col` 对齐自然周）
3. **业务小区折算系数**
   - 3.1 `sales_velocity_alloc_coefficient` ← 需求侧宽表. 分货消速系数
   - 3.2 `sales_velocity_converted_coefficient` ← 需求侧宽表. 卖出折算系数
   - 3.3 生效条件：`speed_coefficient_sell` = true 且 是否国内 = true ；不满足记 1.0
4. **销速基数按侧取值（日均需求量 × 当周分货天数）**
   - 4.1 国内行按 `demand_source_domestic` 取日均需求量；海外行按 `demand_source_overseas` 取日均需求量
   - 4.2 口径 = 激活 → 日均 = `activation_avg_28`
   - 4.3 口径 = SO预测 → 日均 = 目标窗口内 `so_estimate_avg` 合计 ÷ WOS标准周数 ÷ 7（窗口 = `week_col` 起 WOS标准周数 周）
   - 4.4 本周消耗基数 = 日均 × `week_days` （周模式 7 天；月模式最后一周不满 7 天，按实际天数折算，避免跨月周需求被高估）
5. **销速替换（三层，后者优先；替换后同样 × week_days ）**
   - 5.1 真实SO替换：`prefer_so_actual_soldthrough` = true 且该行窗口内有真实SO → 日均换成 `so_actual_avg_28`
   - 5.2 修补替换：`channel_patch_enabled` = true 且 是否修补 = true → 日均换成 日均激活-修补 （分货） / 日均真实SO-修补 （折算），并跳过 5.1
   - 5.3 海外SO新规：`overseas_so_rule_fallback` = true 且海外零激活但 SO 窗口有量 → 日均换成 4.3 的结果；零激活且 SO 窗口无量 → 整行删除
6. **合成销速列**
   - 6.1 `sales_velocity_alloc` = 分货日均 × `week_days` × `sales_velocity_alloc_coefficient` （即本周消耗量）
   - 6.2 `sales_velocity_converted` = 折算日均 × `week_days` × `sales_velocity_converted_coefficient`
   - 6.3 修补行同时写 `replaced_velocity_alloc` / `replaced_velocity_converted` （其余行留空）
7. **口径标记**
   - 7.1 `velocity_source_alloc`：按最终命中写 N天激活 / SO窗口预测(品类口径) / SO窗口预测(零激活新商) / so_actual / 修补
   - 7.2 `velocity_source_converted`：同上折算口径

### 2.3 计算步骤

> 输入 = §2.1 的依赖字段 + §2.2 的配置参数；输出 = 本对象 11 列。

#### 2.3.1 计算逻辑（业务口径）

1. **取原始 WOS**：从需求侧宽表按「交易身份 × EAN × 月份 × 销售周」取 WOS 标准周数，作为原始目标周数。

3. **绩效倾斜**：配置开启倾斜时，把原始 WOS 乘以倾斜系数。
4. **输出**：得到求解实际使用的目标 WOS，并保留原始值与被统一覆盖的标记。

#### 2.3.2 详细步骤

1. **建骨架与原始 WOS**

2. **统一 WOS 参数**

   - 2.2 `uniform_wos_weeks` ← 目标配置. `uniform_wos_weeks`
3. **倾斜系数**
   - 3.1 `skew_ratio` ← 需求侧宽表. 分货绩效倾斜比例（未倾斜行记 0）
4. **合成目标 WOS**
   - 4.1 `use_uniform_wos` = true → `target_wos_processed` = `uniform_wos_weeks`
   - 4.2 `skew_enabled` = false → `target_wos_processed` = `target_wos_original`
   - 4.3 `skew_mode` = 二阶段 → `target_wos_processed` = `target_wos_original` × (1 + `skew_ratio`)
   - 4.4 `skew_mode` = 分组三阶段 → 先按 绩效分组 分组，再 `target_wos_processed` = `target_wos_original` × (1 + 组内系数)

### 3.4 计算步骤

> 输入 = §3.1 的依赖字段 + §3.2 / §3.3 的配置参数；输出 = 本对象 18 列。

#### 3.4.1 计算逻辑（业务口径）

1. **定折算窗口**：按分货周推出开始分货日，再按「卖出折算偏移量」推出窗口截止日与折算天数。
2. **搬库存基础量**：期初库存、总计划入库量、卖出折算系数、业务小区直接搬入。
3. **算卖出折算量**：按库存口径（激活 / SO预估）算窗口内折算销量；有真实SO的用真实SO口径覆盖；再乘业务小区折算系数。
4. **算分货前库存**：期初库存 + 计划入库 - 卖出折算量（按配置决定是否允许负数）。
5. **算分货前 WOS**：分货前库存 ÷ 折算销速，供不参与分货规则 3 使用。

#### 3.4.2 详细步骤

1. **合并表与配置**
   - 1.1 按（交易身份编码, EAN, 月份, 周）与 `B1` 同粒度展开，得到表 1
   - 1.2 把库存配置的 2 个参数、分货周期配置的 `week` 合并进表 1
2. **时间窗口**
   - 2.1 `initial_date` ← 需求侧宽表.期初日期（分货周所在自然月 1 日）
   - 2.2 `alloc_start_date` = `week` 对应 ISO 周的周一
   - 2.3 `alloc_end_date` = `alloc_start_date` - 1 天 + `anchor_extra_days`
   - 2.4 `sold_through_days` = `alloc_end_date` - `initial_date` + 1
3. **基础量透传**
   - 3.1 `base_inventory` ← 需求侧宽表.期初库存数量（缺失按 0 并告警）
   - 3.2 `inbound_supply` ← 需求侧宽表.总计划入库量（缺失按 0 并告警）
   - 3.3 `so_actual_total` ← `B1.so_actual_total`（修补行置 0）
   - 3.4 `sales_velocity_converted` ← `B1.sales_velocity_converted`
   - 3.5 `channel_patch_enabled` ← `B1.channel_patch_enabled`
4. **卖出折算量**
   - 4.1 库存口径 = 激活 → 窗口内激活合计 + 截止日后按日均外推
   - 4.2 库存口径 = SO预估 → Σ(周预估 × 该周落在窗口内的天数 ÷ 7)
   - 4.3 `prefer_so_actual_soldthrough` = true 且窗口内有真实SO → 换成窗口内真实SO合计 + 外推
   - 4.4 乘业务小区折算系数 → `sold_through_qty`
5. **分货前库存与 WOS**
   - 5.1 `inventory_before_alloc` = `base_inventory` + `inbound_supply` - `sold_through_qty`
   - 5.2 `allow_negative` = false 时负值截 0；为实时保留负值（欠货）
   - 5.3 `wos_before` = `inventory_before_alloc` ÷ `sales_velocity_converted`（分母 ≤ 0 时留空）

### 4.4 计算步骤

> 输入 = §4.1 的依赖字段 + §4.2 / §4.3 的配置参数；输出 = 本对象 16 列。

#### 4.4.1 计算逻辑（业务口径）

1. **取供给**：按「EAN × 物料编码 × 规格 × 自然周」从供给侧宽表取可分货数量。
2. **拆大包**：配置开启时，把 1 个 EAN 的供给按比例拆到 N 个料号；关闭时保持 EAN 粒度。
3. **定窗口**：按分货周推出分货开始日、结束日与分货天数（月模式下跨月的那一周截到月末，只算落在本月内的天数）。
4. **扣减与预留**：先扣周级扣减，再按 buffer 比例扣预留。
5. **料号上限截断**：料号粒度下按料号上限截断，得到进入求解器的供给量。

#### 4.4.2 详细步骤

1. **合并表与配置**
   - 1.1 按（国内外, EAN, 月, 分货周）从供给侧宽表取行，得到表 1

   - 2.2 `enabled` = false → 保持原粒度（EAN 粒度下 `material_code` 为空）
   - 2.3 `material_spec` = 国内 S / 海外 A
3. **时间窗口**
   - 3.1 `alloc_start_date` = `week` 对应 ISO 周的周一
   - 3.2 `alloc_end_date` = 周一 + (分货天数 - 1)；月模式下跨月的那一周截到 `planning_month_end`
   - 3.3 `alloc_days` = `alloc_end_date` - `alloc_start_date` + 1（周模式 7；月模式跨月周 < 7，与 `B1.week_days` 必须一致）
4. **原始量与扣减预留**
   - 4.1 `allocatable_qty_original` = 拆包后按料号汇总的供给量
   - 4.2 `weekly_deduction` ← 分货周期配置.`deduction`
   - 4.3 `buffer_reserved` = ( `allocatable_qty_original` - `weekly_deduction` ) × `buffer_ratio`
5. **上限与最终供给**
   - 5.1 `material_granularity` = 料号 → 写 `material_cap`
   - 5.2 `allocatable_qty_processed` = `allocatable_qty_original` - `weekly_deduction` - `buffer_reserved`
   - 5.3 再 min(_, `material_cap`) 截断，截断行数记告警

#### 5.3.1 计算逻辑（业务口径）

### 8.3 计算步骤

> 输入 = §8.1 的依赖字段 + §8.2 的配置参数；输出 = 本对象 16 列。

#### 8.3.1 计算逻辑（业务口径）

1. **分组求解**：按 EAN/料号分组，逐组注水；这一组的供给上限来自可分货量。
2. **级差定档**：按级差模式给赛道等级定档位，并以本轮最高优先级赛道为锚点整体平移。
3. **上限与门店兜底**：先按「合理率上限 × 目标WOS」定每行上限（豁免等级除外），再给门店行预扣最小库存。
4. **阶梯注水**：水位从低到高抬升，供给分完或全部封顶时停，得到初始分货量。
5. **倾斜与扣减**：赛道内倾斜注水得到 skew 量；扣减量与扣减再分配量由秩序扣减规则回写。
6. **合成与水位**：合成注水分货量，并算出分货后 WOS。

#### 8.3.2 详细步骤

1. **建骨架与分组**
   - 1.1 按 (交易身份, 国内外, EAN, 物料编码, 规格, 月份, 周) 取 `B7` 的参与行
   - 1.2 `round` = 第一次分货 / 第二次分货
   - 1.3 按 EAN（或料号）分组，`Q_total` = `B4.allocatable_qty_processed`；`Q_total` ≤ 0 且无结转 → 跳过该组（状态 `skipped_no_supply`）
2. **级差解析与锚点平移**
   - 2.1 按 `tier_ratio_mode` 取各等级档位（自动级差 / 等差步长 / 手动级差）
   - 2.2 取本轮出现的最高优先级赛道为锚点，档位表整体平移（锚点 = 0）
3. **上限与门店 floor**
   - 3.1 非豁免行上限 = 达到「`max_wos_after_ratio` × 目标WOS-处理后」所需件数
   - 3.2 豁免行上限 = 一个目标窗口
   - 3.3 `inventory_in_baseline` = false → 库存不进分子；海外行用 `overseas_ladder_cap` 放宽
   - 3.4 门店行预扣 clip(门店最低库存 − `S_1`, 0, ∞)；缺口总和超过可分配总量 → 该组失败
4. **阶梯注水**
   - 4.1 水位从全体最低有效水位起按固定步长抬升
   - 4.2 逐行 需求 = clip(水位 × 目标WOS × 周消耗 − 库存基线 − 已分, 0, 上限 − 已分)
   - 4.3 供给分完或全部封顶时停 → `alloc_qty_init`
   - 4.4 `skew_in_track` = true → 赛道内倾斜注水 → `alloc_qty_skew`
5. **扣减与合成**
   - 5.1 `deduction_qty`、`alloc_qty_deduction` 由秩序扣减规则回写（第二次分货实例置 0）
   - 5.2 `alloc_qty_water` = 无倾斜 `alloc_qty_init` + `alloc_qty_deduction` − `deduction_qty`；有倾斜用 `alloc_qty_skew` 替换 `alloc_qty_init`
   - 5.3 `wos_after` = (分货前库存 + 本轮累计分货量) ÷ 日均销速

3. **合成最终分货量**：注水分货量 + 保底量。

   - 副作用：月模式下跨月的那一周分货量会明显低于整周（因为目标占用 水位 × 目标WOS × 周消耗 也按天数缩小）。需确认这是业务要的效果，而不是「最后一周仍按整周全货」。
7. **Q7** 多周库存滚动是否同步按天数扣消耗：引擎多周滚动目前是 `S_i = S_i + 本周分货量 − 一周消耗` （整周口径）。若 `B1` 的周消耗按 `week_days` 折算，滚动公式也必须同步改成扣 `week_days` 天的消耗，否则周与周之间的库存水位会与实际消耗对不上。
